# Conduit: compilation, dispatch and bytes

[Research 97](../../../../docs/design/research/97-conduit-dispatch-profiles.md)
explains the finding, attribution limits, before/after and remaining costs.
`provenance.json` pins compilers, source-diff fingerprint, served bundle hashes
and archive hashes. `validation.json` separates local suites from the hardware
gate still owed on a supported Linux host.

`cpu.json.gz` and `allocations.json.gz` each contain 270 complete CDP records
(three operations × three candidates × thirty fresh pages), plus run metadata.
Each record retains the CPU profile, timeline and, in the allocation pack,
sampled heap. Unzip a pack and extract a record's `profile` to load it into
Chrome's JavaScript profiler. Allocation and CPU-only passes are separate.
`timing.json` contains the independent untraced comparison and its trace pass;
all raw observations remain, including load. `code-excerpts.json` retains the
complete readable handler excerpts. The three `.mjs.gz` files are the actual
release JavaScript served, not a reconstruction from excerpts.

`cpu-attribution.json` and `allocation-attribution.json` are generated by
`bench/conduit/attribute.mjs`. `.tsv` maps record module source ranges and global
names in those exact bundles. The measurement-only `bundle-map.patch` adds
stderr maps; it is not part of the production compiler. Build it in isolated
checkouts with separate caches, save stderr, and byte-compare the resulting
bundle against the uninstrumented compiler before using its maps.

Reproduce from the repository root, in the pinned dev shell. Install the UI
benchmark's pinned dependencies (`npm ci` in both Solid app directories) and
supply a local Chrome executable. All compiler builds/tests use `zorg`.
The original before compiler is `ff82485e5`; the frozen after compiler's base
and source fingerprint are in `provenance.json`. Archive hashes distinguish
an exact replay from a new run with a later compiler or browser.

```sh
direnv exec . zorg build
BENI=zig-out/bin/beni BASELINE_BENI=/path/to/before/beni \
  direnv exec . node bench/conduit/measure.mjs > counts.json
# measure.mjs calls the baseline browser-direct-before-release. The historical
# batch named that unchanged bundle browser-direct-start-release instead.
direnv exec . node bench/conduit/time.mjs --samples=30 \
  --baseline=browser-direct-before-release --chrome="$BENI_CHROME" > timing.json
direnv exec . node bench/conduit/time.mjs --samples=30 \
  --baseline=browser-direct-before-release --chrome="$BENI_CHROME" \
  --profiles=zig-out/cpu-profiles --compile-trace > cpu-summary.json
direnv exec . node bench/conduit/time.mjs --samples=30 \
  --baseline=browser-direct-before-release --chrome="$BENI_CHROME" \
  --profiles=zig-out/heap-profiles --compile-trace --allocations > heap-summary.json
```

Replay attribution without Chrome or a compiler: unpack `tea.mjs.gz`,
`before.mjs.gz`, `after.mjs.gz` into respectively
`$WORK/browser-tea-release/_main.mjs`,
`$WORK/browser-direct-start-release/_main.mjs` and
`$WORK/browser-direct-release/_main.mjs`; then:

```sh
direnv exec . node bench/conduit/attribute.mjs --work="$WORK" \
  --subjects=browser-tea-release,browser-direct-start-release,browser-direct-release \
  --maps=bench/conduit/results/2026-10-15-profiles/after \
  --before-maps=bench/conduit/results/2026-10-15-profiles/before \
  --profiles=bench/conduit/results/2026-10-15-profiles/cpu.json.gz > replay.json
```

Change `cpu.json.gz` to `allocations.json.gz` for the heap pass. Brotli peeling
is an ordered accounting convention, not independently compressible modules.
No interpolation assigns missing stacks to an application function. Allocation
sampling covers a broader window than the exact event marks and cannot provide
an isolated allocation-only CPU percentage.

`sweeps.json` is the full report-87 sweep set, 79 operation/size cells and 10,980
observations, with before/fixed release, tea, vanilla and Solid 2. `sweep-code.json`
compares all 57 emitted release programs, including normalized hashes.
`touched-controls.json` adds Solid 1 and P3 on the ten programs whose bytes
changed. P3 has no tree implementation; five explicit skips are retained.
All supported cells complete with no failures. Reproduce in `bench/ui`:

```sh
direnv exec ../.. node scaling.mjs --full --untraced \
  --subjects=beni-release,beni-direct-release,beni-start-direct-release,vanillajs,solid2 \
  --variants=start=/path/to/before/beni --beni=/path/to/after/beni \
  --chrome="$BENI_CHROME" --out=/path/to/sweeps.json
# Add --sweeps=live,tree and solid1,p3 to --subjects for the extra controls.
```

The scaling build fetches pinned, checksum-verified CSS; the runner now refuses
a missing CSS setup. A preliminary run without CSS was stopped and discarded.
An earlier local suite overlapped a compiler replacement; it was stopped and
superseded by the sequential frozen-compiler validations in `validation.json`.
Neither interrupted run supplies accepted observations here. Pilot CPU/heap and
sharing-ablation runs remain local scratch; only the finished paired passes
are archived. No first-use cost is hidden through extra target-key warm-up.
