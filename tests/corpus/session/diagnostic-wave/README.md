# Resident diagnostics (#1539)

This corpus exercises the existing public beni.Session API through a separate executable, not through a new compiler flag. The normal CLI and watch/serve recreate Session each invocation, so they cannot reproduce stale worker diagnostics across runs. The external driver imports the ordinary beni module, copies these disk revisions into Main.beni, refreshes the same public SourceStore, and invokes Session.run four times. It emits only ordinary rendered diagnostics, Summary counts and a cache-hit observation from public profile counters. It must never inspect workers or clear diagnostics itself.

The exact golden covers warning once, the same unchanged cached warning once, a new type error once and repaired source with no diagnostics. The registered session_api_test process drives the executable at jobs1 and8. The production in-source test is supplemental. Before/after evidence must use identical driver and corpus, changing only the existing run-start aggregate/worker cleanup in Session.zig; before must fail the exact golden, after must pass. No language, user CLI, budget or ownership rule changes. This supplements the frozen2f3 consumer checkpoint without modifying its archive.
