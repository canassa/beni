# 61 — How often a TEA program's writes are known at compile time

*2026-10-08. The compiler-side feasibility spike research 58 §9 (iii) asks for before slices 3–4
of message-indexed rendering are built: per `Msg` constructor, can a whole-program compiler pin
down what the update branch writes (W1), and per view hole, can it prove the hole never changes
(W2)? Measured with a throwaway classifier over `beni dump --stage=ast`
(`bench/writesets/classify.mjs`); nothing in the compiler changed. Every figure below is
**[measured]** by that tool unless marked otherwise, and every number is reproducible with the
commands in §2.4.*

---

## 0. The answer in six sentences

1. Of **231 constructors** in 71 TEA programs, **none is `*`**: 100% have a bounded write set
   (exact 61%, indexed 25%, structural 13%), so research 58's kill criterion — "fewer than
   roughly two thirds bounded" — is **not met, by a wide margin**, and slices 3–4 should not be
   cut to constancy and the dirty set.
2. **Exact + indexed is 87%** of all constructors (85% if a constructor that replaces a list
   wholesale does not count), but that figure is carried by the platform fixtures, whose
   updates are a counter, a log append or nothing at all (42 constructors, 18%, write nothing).
3. In the **applications** — TodoMVC and the table app — exact + indexed is **53%** (10 of 19
   distinct constructors; 47% over the 59 constructors of all six builds) and **structural is 47%**: half of
   what a real page does is the `List.map (λr → if r.id == id …)` and `List.filter` idioms,
   which pay off only with identity-preserving `List.map` plus a diff (research 58 §5(a)).
4. The edit-script recognisers research 58 §9 slice 4 lists first — `List.update k`, `set`,
   `swap`, `removeAt` — have **zero uses** in any TEA or DOM page in the repository; the only
   indexed edits that occur are appends (57 writes), `[]` (2) and, in the renderer
   fixtures, `take`/`drop`/prepend.
5. Constancy (W2) proves **27% of holes** static or literal overall, but **0 of 16** in TodoMVC
   (every path it reads is written by some message) against **13 of 16** in the table app
   (its buttons are a helper called with literals): the constancy win is real on component-style
   pages and append-only lists, and nil on TodoMVC.
6. The `*` patterns exist — restoring the whole model from a decoder, a recursion over the
   model, an undo snapshot — and the classifier finds them in a validation program, but the
   corpus contains none, which is the largest threat to this result (§7).

## 1. The corpus

**Measured (the "TEA corpus"):** every program in `tests/corpus/browser/tea/` — 62 files and
5 directories (`Counters`, `HttpDefect`, `StorageFaults`, `TwoPrograms`, `TypedKeys`), 67
programs, not the ~68 the brief estimated — plus `bench/ui/apps/beni/Main.beni` (the
js-framework-benchmark table app) and the four TodoMVC builds in `bench/todomvc/apps/beni/`
(`NoEditing`, `NoRouting`, `NoStorage`, `Sandbox`). A file that mounts several programs
(`Browser.programs`) is one row; each mounted program is analysed on its own.

**Excluded, no real `update`:** `ApplicationNotHttp` (`update = λ_ m → ( m, Cmd.none )`, no
`Msg` type) and the `shell` program of `LinkOutsideMount` (`update = λ_ m → m`). Rule: a program
unit is excluded when its message type has no constructors of its own and no message writes the
model. No `Defect*` fixture was excluded: each has a message type of its own and an `update` that
dispatches on it, most with a counter or a log beside the defect branch (`Inc`, `Tick`, `Go`…); a
`Debug.todo` branch never returns, so it writes nothing. In `DefectReleaseSuspends` and
`DefectReleaseThrows` every message only issues a command; their four constructors are counted,
as writing nothing.

**Measured separately (the "renderer corpus", Appendix B):** the `Browser.program` pages of
`tests/corpus/browser/dom/` (37 after the two exclusions below) and the two pages at the top of
`tests/corpus/browser/`, 39 programs. They are TEA-shaped (`init`, `update`, `view`) but were written to exercise the renderer, so they are not
counted toward the verdict; they are a second opinion on the idioms. `dom/LetChain.beni` (a
generated 4 341-line `let` chain, a build-budget stress test) and `dom/SafeUrlConstant.beni` (no
message) are excluded.

**Looked at and left out:** `bench/ui/apps/micro/beni/*` (generated 50-field instruments; one
helper called 700 times with literals would drown the hole counts) and
`bench/ui/apps/scaling/*` (pages generated by JavaScript for the sweeps). Both are instruments,
which research 58 §8 item 4 says not to use as yardsticks. No other TEA program exists in the
repository (`platforms/browser-tea` holds the library, `bench/minify/empty-page` an empty page).

## 2. Method

### 2.1 The tool

`bench/writesets/classify.mjs` (Node, no dependencies) runs `beni dump --stage=ast` on every
module of a program, finds each record literal that has both an `update` and a `view` field (the
argument of `Tea.sandbox`, `Tea.element`, `Tea.application`, `Browser.program`, inline or through
a definition), and runs a small abstract interpreter over the AST:

- **`update`** is evaluated once per constructor `C` of the message type, with the message bound
  to a marker that only `C`'s patterns match (so `case msg of`, `case ( msg, x ) of`, nested
  payload patterns and `λUp n →` all select the right branches) and the model bound to
  *O(root)*, "the old model, untouched". For `Tea.element`/`Tea.application` the model is the
  first component of the returned pair; commands are ignored.
- **`view`** is evaluated with the model bound to *O(root)*; every markup hole is collected with
  its **read set**, the model paths its expression reads.

The abstract values are: *O(p)* — the old model's value at path `p`; *F(reads, why)* — a value
the analysis cannot relate to the old model, with `why` set when it came out of a call it did not
summarise; record update, record literal, tuple, a join of alternatives (`case`/`if`); *Lst(base,
op)* — a recognised edit of a list; a closure; ⊥ for `Debug.todo`.

### 2.2 The rules for writes (W1)

Every **user function** is inlined at its call site with abstract arguments, across modules
(`Counter.update` in `Counters`); a call already on the inlining stack is a recursion and yields
an opaque value. **Core and platform functions** are opaque except: `List.map`/`indexedMap`/
`filter`/`update`/`set`/`push`/`pop`/`insertAt`/`removeAt`/`swap`/`take`/`drop`/`slice`/
`sort`/`sortBy`/`sortWith`/`reverse`/`initialize`/`append`, `++`, `[ …xs, x ]`, `[ x, …xs ]`,
`[]`, `Debug.log` (returns its value), `Debug.todo` (⊥), `Html.map`, `Tuple.first/second`.

The update's result is compared with the old model path by path:

| result at path `P` | write | class |
|---|---|---|
| *O(P)* — the same value | nothing | — |
| record update / literal | recurse into each named field | — |
| a scalar or a constructor computed from anything (`count + 1`, `Just x`, `not on`) | `P` | exact |
| an opaque call's result at a non-root `P` (`Maybe.map model.editing …`) | `P` and everything below | exact |
| a list at `P` replaced by a literal or a list not derived from `P`'s own old list (a payload, `build 1000`, `List.range`) | `P` | exact, flagged **list replaced** |
| `++ [x]`, `[ …xs, x ]`, prepend, `List.push/pop/take/drop/insertAt/removeAt/swap/set/cons`, `[]`, append of another list, `initialize` — on `P`'s own old list | `P`'s spine | **indexed** |
| `List.update xs k f` on `P`'s old list | element `k`, with `f`'s writes below it | **indexed** |
| `List.map`/`indexedMap` of `P`'s old list | each element, with the lambda's writes below it (identity map: nothing) | **structural** |
| `List.filter` of `P`'s old list | `P`'s spine: removals, order kept | **structural** |
| `sort`/`sortBy`/`reverse` of `P`'s old list | a permutation | **structural** |
| the **whole** record model from an opaque call, a recursion, or another path's value (an undo snapshot) | everything | **`*`** |

A constructor's class is the most general class among its writes (exact < indexed < structural <
`*`), joined over every branch it can take; a constructor that writes nothing is exact with an
empty set. A **list replaced** constructor stays in its class but is counted separately, because
it needs keyed reconciliation for that list (as vanilla's "create rows" does). `++` on a `String`
and on a `List` are told apart by the type of the path, taken from the `Model` alias.

### 2.3 The rules for holes (W2)

A hole is a braced attribute (`value={…}`, `class={…}`), a child expression (`{…}`), the `each`
of a `For`, or the scrutinee of a `case`/`if` that chooses markup. `on*` attributes are event
bindings, not holes (delegated, never patched; counted separately). A helper that returns markup
is inlined at each call site, so its holes are counted per site with the arguments of that site;
`Html.map` is transparent; a `Tea.Document` contributes its `title` as a hole. Inside a `For`, the
row variable is bound to *O(list.[\*])*.

| class | rule |
|---|---|
| **static** | no write of any constructor conflicts with any path in the read set |
| **literal-init** | static, and `init` gives every read path a literal (an empty read set — a helper called with literals — counts) |
| **static (key)** | a row hole of a keyed `For` that reads only the key field: per row instance it cannot change |
| **dynamic** | everything else |

A write **conflicts** with a read when one path is a prefix of the other. A **spine** edit (push,
filter, …) conflicts with reads of the list and its ancestors, not with an existing row's fields —
except in an **unkeyed** `For`, where an edit that shifts positions (anything but an append, a
pop, a `take`, a clear), or any edit when the rows are a filter/sort/map of the list, changes what
an existing row shows. So "static" includes the rows of an append-only log: each row is written
once, at its mount.

### 2.4 Reproducing it

```sh
BENI=zig-out/fast/bin/beni node bench/writesets/classify.mjs              # every constructor, write and hole
BENI=zig-out/fast/bin/beni node bench/writesets/classify.mjs --table      # the table of §4
BENI=zig-out/fast/bin/beni node bench/writesets/classify.mjs --list       # Appendix A
BENI=zig-out/fast/bin/beni node bench/writesets/classify.mjs --set=dom --table   # Appendix B
BENI=zig-out/fast/bin/beni node bench/writesets/classify.mjs bench/writesets/validate/Main.beni
```

It needs a `beni` that has `dump --stage=ast` (master of 2026-10-08), runs in about 3 s, and
`--json` gives the raw result.

### 4.2 What the writes are

Over the TEA corpus's 227 distinct writes (per constructor): a computed value at a fixed path 114,
an append 57 (`++ [x]` 54, append of another list 3), `List.filter` 19, `List.map` 18, an opaque core call at a
fixed path 11 (`Maybe.map`, `not`, `Time.toMillis`, `String.toUpper`, `Maybe.withDefault`), a list
replaced 4, `[]` 2, `List.indexedMap` 2. The renderer corpus adds prepend (6), `take` (5), `drop`
(1), `reverse` (2) and five lists rebuilt from another list. **`List.update`, `List.set`,
`List.swap`, `List.removeAt` and `List.insertAt` appear nowhere** — not in an update branch, not
anywhere in a page (`grep` agrees).

## 5. The causes of `*`

None occurs in either corpus, so this list is of the patterns the rules would mark `*`, each
checked on the validation program or by reading the rules:

| pattern | example | language idiom or test artefact |
|---|---|---|
| whole model from a core function | `Restore s → Maybe.withDefault (decode s) model` — restoring state from storage, a URL or JSON | **idiom**: every persisted SPA has one; it is a rare message (a load), and its handler is today's full patch, so the cost is paid once |
| a recursion over the model | `Repeat n → bumpTimes n model` | **idiom**, rare in TEA (a loop over messages); summarising a tail recursion that only touches named fields would recover it |
| the whole model from another of its paths | `Undo → prev` from a history list | **idiom** (undo/redo); every path written, the handler is the full patch, which is right |
| `foreign` | — | unreachable: only core and platforms write `foreign` (rule 6), and every platform call in the corpus lands at a fixed path, so it is exact there |
| unresolved `where` evidence | — | not present: no page's update calls a constrained helper on the model |

**Not `*`, but coarse:** an opaque core call at a fixed path (`editing = Maybe.map model.editing
…`) writes the whole path, one level coarser than the field it changes (11 writes); a list
replaced by a payload or a builder (4 constructors in the TEA corpus, 8 in the renderer's) is
exact by path and needs a keyed reconcile for the list. No test artefact produced a `*` or a
coarse write; the artefacts' effect runs the other way — they make the corpus look *more* exact
than an application (§0 item 2).

## 6. The verdict against research 58's criterion

**Bounded = exact + indexed + structural = 100% of constructors** (231 of 231; 59 of 59 in the
applications; 107 of 107 in the renderer corpus). The criterion's threshold is two thirds; it is
cleared everywhere, by every program, so by its own terms **the architecture is not a benchmark
win and slices 3–4 stay**.

**Exact + indexed — what pays without identity-preserving `map` and a diff — is 87% overall but
47–53% in the applications.** In the corpus's two real applications, about half of all messages
are structural, so the second half of slice 4 is not an optional extra: without it, TodoMVC's
`Toggle`, `ToggleAll`, `Destroy`, `ClearCompleted`, `EditKey` and `EditDone` and the table's
`Update`, `SwapRows` and `Remove` keep today's whole-list walk for the list they touch (they are
still specialised for every other group of the page, so this is no regression).

## 7. Threats to validity

- **The corpus is beni's own test suite.** 65 of the 71 programs are platform fixtures with one to
  seven messages, written by the people who built the platform; they have no persistence restore,
  no undo, little nesting (`Counters`, `LatestTagger`), no form with many fields. That no `*` appears
  says the idioms that cause it are absent here, not that they are rare in the wild. The
  application figures rest on two programs (five builds of one of them).
- **The classifier is a prototype, not the analysis slice 3 would build.** It has no types beyond
  the `Model` alias, inlines every user function rather than summarising it, approximates patterns
  over the old model by the matched path, and counts a helper's holes per call site. Where it can
  err, it errs coarse (a coarser path, `structural` where a person sees a swap), never finer —
  as far as the 24 hand checks reach. A rule that is simply wrong would be caught by the
  differential test research 58 §8 item 2 requires of the real pass; this tool has none.
- **"Static" counts a row hole as static when each row instance is written only at mount.** That
  is the per-instance meaning slice 2 needs; a reading that requires the hole to be static for
  the page's lifetime would move all 26 to dynamic (every one is a row hole).

## 8. What this means for the order of work (research 58 §9)

1. **Keep slices 3 and 4.** The kill criterion is not met; per-constructor handlers have a bounded
   write set to work from on every message measured.
2. **In slice 3, a constructor that writes nothing should skip the flush entirely.** 18% of the
   TEA corpus's constructors are command-only (a fetch, a navigation, a timer start). Whether
   today's runtime already skips the render when `update` returns the same model was not checked
   here; with W1 the compiler knows it statically, for free.
3. **Reorder slice 4: append/clear first, then identity-preserving `List.map` plus `$diff`, then
   filter.** Ordered by use, the edit scripts that matter are append (57 writes), clear and replace;
   the `map`-if-id idiom and `filter` are 47% of application messages. `List.update k`, `set`,
   `swap` and `removeAt` have no user in the repository: build their recognisers last, or when a
   page uses them — or change the idiom, since beni has no Elm-compatibility weight to carry (the
   table app's `SwapRows` could be `List.swap rows 1 998`, which would make it indexed). A
   remove-by-key recogniser for `List.filter xs λr → r.id ≠ id` (TodoMVC `Destroy`, the table's
   `Remove`) is worth more than all four.
4. **Slice 2 (constancy) pays on component-style pages, not on TodoMVC.** 27% of holes overall, 13
   of 16 on the table app (the helper-with-literals buttons), 0 of 16 on TodoMVC. It still belongs
   before slice 3 for bytes and mount time, but it should not be credited with per-message speed
   on list-heavy pages.
5. **Collect a third yardstick before slice 4 is specified:** an application with persistence,
   undo, a form and a nested component (research 58 §8 item 4 already calls for honest
   yardsticks). The `*` rate is the number this study could not measure; one such page would.
