\textbf{The property.} An update is accepted when its operand's cell is \emph{unique at the site}: every other holder of that cell is dead at that point. A holder is dead when no later read goes through it. A read that comes \emph{before} the update is therefore never sharing, however many there are; a read that comes \emph{after}, through any path the checker can see, is. This is Boyland's alias burying (2001 §3.2, p. 13: aliases may exist “simply … all be dead”) and Rust's non-lexical borrow (RFC 2094, “Liveness”), applied to a language with no references, and it is exactly what a plain array needs: the write is invisible iff nobody reads the old version afterwards.

\textbf{Why beni can infer it.} Three facts of the language do most of the work. (1) \textbf{Strict, left-to-right evaluation in source order} (\code{language.md} §6, \emph{Evaluation order}): the order a read and a write happen in is the order they are written, so “before” is syntactic, as Futhark chose (2022 post, ll. 80–105) and as Smetsers et al. formalised with “preliminaries” and “alternate” argument classes (1994 §4, p. 9). (2) \textbf{Every call is saturated and there is no currying} (\code{language.md} §6.7): the one thing every uniqueness type system found “far from trivial” — a partial application silently holding a unique argument (Clean report §9.4.1 p. 97; Barendsen \& Smetsers 1996 §7 p. 18; de Vries 2007 §4.2; Lorenzen et al. 2024 §6.4 p. 22, who say the complications “go away if we imagine a change to the language forbidding currying”) — does not exist. A closure is a written lambda, and a lambda's captures are visible. (3) \textbf{The checker already infers two bits per function type and solves them as a directed graph after each module, publishes them in the interface and hashes them} (\code{checker-v2.md} §26; \code{transparent-effects-proposal.\allowbreak{}md} §14). Ownership rides in the same seats: a few more facts per function-type site, the same $\sqsubseteq$ edges, the same interface block, the same firewall.

\textbf{The analysis.} Per function, in one forward pass over the body in evaluation order: for each variable and record path, the set of cells it may hold (a directional, Andersen-style flow, never unification: Emre et al. 2023 measured unification poisoning 85 \% of tmux's pointers from four unsafe ones, §5, p. 94:10, and Table 2, p. 94:14); then a backward liveness pass per (variable, path); then, at each demand, the check. Calls use the callee's summary. A recursive group starts from the most optimistic summaries — everything borrowed, every result fresh — and weakens to a fixpoint, the search Aspinall, Hofmann and Konečný prove finds the best typing for first-order programs (2008 §6.2, p. 36) and the direction Lean's borrow inference (Ullrich \& de Moura 2019 §5.2, p. 6) and Brandon et al. (2026 §4.4, p. 16: “a least fixed point … justified by Knaster–Tarski”) take. The cost is linear in the body per round, with a round count bounded by a two-step lattice per parameter; it fits \code{fast-compiler.md} §2's budget the way the effect pass did ($\le$ +10 \% of check).

\textbf{What it needs from the rest of beni.} \code{core/}'s update primitives declare their summaries (they are \code{foreign}, which already declares a rung and \code{sync}; one more word). The runtime that calls \code{update} must \emph{hand the model over}: keep no content holder of any list in the old model after the arm runs. Today's \code{browser} runtime keeps every rendered list (\code{backend.md} §15.11; research 42 §6.1: “never in place”), so under this rule every edit of a rendered list in \code{update} would be an error on that platform. \code{browser-direct} was designed so that identity compares and in-place writes never meet (§7.4's two rules), and its handoff protocol is specified here (§5.9). Values a program hands to a command, a fiber, a \code{Ref}, \code{Js} or a sibling are shared from then on; the write-set interpreter already computes which model paths escape that way (§7.4 condition 2), and the checker reads it at the boundary.

\textbf{What it costs.} Every program that keeps an old version and then edits — an undo history, a “before and after” comparison, a test that holds the input, a command that captured the list — is rejected until it writes \code{List.copy}. Persistent sharing becomes an explicit O(n) copy; the trie goes; prepending in a loop is O(n) again except where the building-loop rule applies. Closures that consume a capture may be called at most once, so \code{List.\allowbreak{}map xs (λx → List.\allowbreak{}push acc x)} is an error and \code{List.foldl} is the way. Interface churn: a body edit that changes a \code{pub} function's summary re-checks its importers, as inferred \code{where} clauses already do (research 19 §4). And the owner's own programs show where the demand would land: TodoMVC and Conduit call \textbf{none} of \code{set}, \code{push}, \code{update}, \code{swap}, \code{pop}, \code{insertAt} or \code{removeAt} — they write \code{List.map}, \code{List.filter} and \code{++} — so under the rule as asked the only demands in them are the \code{++} sites (\code{List.append}: one in TodoMVC's Enter arm, \code{model.\allowbreak{}todos ++ [ new ]}, and four in Conduit on literal left operands), and nothing else changes unless the same-shape rebuilds (\code{map}, \code{filter}, \code{indexedMap}) join the demand set (§10, change 1).

\textbf{The recommendation} (§11): build the checker as a \emph{report-mode pass first}, exactly as the write-set analysis was built (\code{write-sets.md} §8), run it over \code{core/}, the corpus, TodoMVC and Conduit, classify every rejection as real sharing or a checker limit, and decide the error against those numbers. The rule's soundness is good; its value depends on two things this document cannot settle from a desk: the rejection rate on code people actually write, and whether the owner wants \code{map} and \code{filter} in the demand set.
