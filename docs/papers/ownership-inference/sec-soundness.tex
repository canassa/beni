\section{Soundness}
\label{sec:soundness}

This section states the guarantee and sketches an argument for it. The argument has the shape of
standard proofs for in-place update \citep{aspinall2008usage,bernardy2018linear}, and its lemmas are
the usual ones for a flow analysis; but it is a sketch over an informal semantics of a real
language, it has not been mechanised or independently reviewed, and it rests on ten assumptions about
code the checker does not see (\S\ref{sec:soundness-assumptions}). We present it as the argument we
believe, together with the places where we think it is weakest.

\subsection{The claim}

\begin{theorem}[The two semantics coincide]
\label{thm:main}
Let $P$ be a program every module of which the checker accepts: every demand satisfies \Known,
\Unescaped, \Dead\ and \Disjoint\ against the published summaries of its callees, and every recursive
group's summaries are validated. Suppose assumptions A1--A10 hold of the runtime, the core library and
the platforms. Then for every sequence of host events, the value semantics $S_v$ and the update
semantics $S_u$ produce the same \emph{trace}: the same sequence of observations, where an
observation is a byte written to an output stream, a DOM write, a call into a \code{foreign} sibling
or a \code{Js} operation with its arguments marshalled by value, and the program's exit.
\end{theorem}

$S_v$ is beni as it is today, and $S_u$ is what the backend would emit under the rule
(\S\ref{sec:compiler-backend}). The statement mirrors Aspinall, Hofmann and Kone\v{c}n\'y's soundness
theorem, in which in-place evaluation is both correct and complete with respect to a safe functional
evaluation \citep[Thm.~5.8]{aspinall2008usage}, and Linear Haskell's theorem that ``the semantics with
in-place mutation is observationally equivalent to the pure semantics''
\citep[Thm.~3.9]{bernardy2018linear}. We state it over traces rather than final values because beni's
observations are effects at the JavaScript boundary.

\subsection{Instrumented semantics: versions and stale references}

We add ghost state to $S_u$. Every cell $c$ carries a \emph{version} $\mathit{ver}(c) \in \mathbb{N}$,
incremented by each in-place write. Every reference to $c$, wherever it is held---a local, a field, an
element, a closure environment, a fiber, a runtime slot, a JavaScript variable---carries the version
at which it was created or last obtained from a current reference: reading a field of a current record
yields a current reference, and a binding \code{y = x} copies $x$'s stamp. A reference is \emph{stale}
when its stamp is below $\mathit{ver}(c)$.

The correspondence to $S_v$ is a function on references: the reference $(c, k)$ of $S_u$ corresponds to
the array $c_k$ of $S_v$, the $k$th array in the chain $c_0 \to c_1 \to \cdots$ that $S_v$'s updates
built. Contents agree for current references by construction: the write that raised $\mathit{ver}(c)$
from $k$ to $k+1$ in $S_u$ is the copy that made $c_{k+1}$ from $c_k$ in $S_v$, with the same element
written at the same index. The contents of a \emph{stale} reference $(c, k)$, $k < \mathit{ver}(c)$,
disagree with $c_k$; that is the only place the two heaps differ.

\begin{lemma}[No stale read]
\label{lem:stale}
If no step of $S_u$ dereferences a stale reference, the two traces are equal.
\end{lemma}
\begin{proof}[Proof sketch]
By bisimulation, relating configurations that have the same expression with every reference mapped
by $(c, k) \mapsto c_k$. Every step preserves the relation: every step reads only current references,
whose contents agree, and the only step that writes---an accepted update---produces on both sides a
reference whose contents agree ($c_{k+1}$ and $(c, k+1)$). An observation marshals by value from
current references, so it agrees.
\end{proof}

The theorem therefore reduces to: \emph{in an accepted program, no stale reference is ever
dereferenced}.

\subsection{Lemmas}

\begin{lemma}[Flow facts over-approximate the heap]
\label{lem:flow}
At every program point of a declaration, for every cell $c$ reachable from the frame's locals through
a path, there is a holder $(x, q)$ with $c \in A(x)@q$, or $\top \in A(x)@q$, or $c$ is marked escaped.
\end{lemma}
\begin{proof}[Proof sketch]
By induction over the transfer rules of Table~\ref{tab:transfer}: each rule's result contains every
cell the construct can produce from its parts, and a call's result is bounded by the callee's
$\mathit{res}$ (Lemma~\ref{lem:summary}). The path cut yields $\top$, and every construct without a
summary yields $\top$ and escape.
\end{proof}

\begin{lemma}[Exclusive contents]
\label{lem:excl}
If a container path carries $\excl$ at a point, then every concrete cell reachable through it is stored
at exactly one position of that container and has no holder other than the container's path.
\end{lemma}
\begin{proof}[Proof sketch]
By induction over the rules of \S\ref{sec:model-excl}. Setting the flag requires each stored cell to be
unique at the store (Lemma~\ref{lem:dead}, reading the store as a demand that does not write). A
destructive read overwrites the one position before any other read, so the element it hands out has
the callback as its only holder. Every other store or read clears the flag.
\end{proof}

\begin{lemma}[Liveness over-approximates future reads]
\label{lem:live}
If $\live(h, p)$ is false, then no execution continuing from $p$ dereferences the cell held by $h$
through $h$.
\end{lemma}
\begin{proof}[Proof sketch]
The uses of \S\ref{sec:model-liveness} cover every construct that can read a value or hand it to
something that can: a direct read; a call, by the callee's summary and Lemma~\ref{lem:summary}; a
return; a store; a capture, by the closure's summary and the $\mathit{calls}$ and $\mathit{escapes}$
facts of the function it is passed to; and the catch-all for anything unseen. Backward propagation in
instruction order is evaluation order, so ``after $p$'' is well defined.
\end{proof}

\begin{lemma}[Summary soundness]
\label{lem:summary}
For every call $f\,\bar a$ evaluated in $S_u$, with argument cells $C_1, \ldots, C_n$:
\begin{enumerate}
\item $f$ writes a cell of $C_i$ only if $\mathit{use}(i, q) = \consumed$ for the path at which it sits;
\item if $\mathit{use}(i, q) = \borrowed$, then after the call no cell of $C_i@q$ is reachable from the
result, from any place that outlives the call, or from any closure that can still be called;
\item the result's cells at $q'$ are within $\mathit{res}(q')$ instantiated with the arguments, where
$\fresh$ denotes a cell that no holder other than the result holds;
\item $\mathit{calls}$ bounds the number of calls $f$ makes to argument $j$ in any execution,
$\mathit{escapes} = \mathit{no}$ means that no reference to it outlives the call, and $\mathit{supply}$
and $\mathit{need}$ bound what $f$ passes to it and keeps from it.
\end{enumerate}
\end{lemma}
\begin{proof}[Proof sketch]
By induction on the depth of the call tree of the execution. For a non-recursive $f$, the summary was
read off its body under Lemmas~\ref{lem:flow} and~\ref{lem:live} using its callees' summaries, which
hold by the induction hypothesis. For a recursive group, the validated fixpoint is a consistent
assignment: each body checks against the final summaries, so the induction hypothesis for the
recursive calls is exactly the summary, and the body's own analysis yields the summary again. The
optimistic start does not weaken the argument, because only the validated assignment is used; the
search merely finds the best one. For a \code{foreign} or an asserted summary, the summary is declared
and the implementation is trusted (A2, A8).
\end{proof}

\begin{lemma}[Dead aliases]
\label{lem:dead}
At an accepted demand $u$ on operand cell $c$, every reference to $c$ other than the one the demand
returns is dead: it is never dereferenced afterwards, by the caller, or by the callee during the call.
\end{lemma}
\begin{proof}[Proof sketch]
By \Known\ the cell is known. By \Unescaped\ it is not escaped, so (Lemma~\ref{lem:flow}) every
reference to it is accounted for by a holder $(x, q)$ of the current frame, or of a caller's frame
through the chain of parameters. By \Dead\ each local holder is dead after the call
(Lemma~\ref{lem:live}). By \Disjoint\ no other argument and no capture of a function-valued argument
holds $c$, so nothing the callee reads during the call---its other parameters, its callbacks'
environments---reaches $c$; the callee's own locals that hold $c$ are aliases of its consumed
parameter and are checked by the callee's own side conditions with the parameter as operand. Each
parameter-path holder was checked at the caller's call site, where the same conditions applied to the
caller's holders (Lemma~\ref{lem:summary}, clause 1, transfers the obligation). Holders in closure
environments are covered because a closure is itself a holder whose liveness bounds its captures'
(Lemma~\ref{lem:live}); a closure that may consume a capture is $\mathit{once}$, an affine value used
at most once and only where $\mathit{calls} \le 1$, and its consumed captures are checked at its
creation against its own liveness.
\end{proof}

\begin{proof}[Proof sketch of Theorem~\ref{thm:main}]
By Lemma~\ref{lem:dead}, after the write at $u$ every reference to $c$ other than the one the demand
returns is dead, hence never dereferenced, and the returned reference is current. Induction over the
steps of the execution gives the hypothesis of Lemma~\ref{lem:stale}.
\end{proof}

\subsection{Assumptions}
\label{sec:soundness-assumptions}

The theorem is conditional on the following assumptions about code the checker does not analyse. A
false assumption produces a wrong answer, not a false error, which is why we list them here rather
than among the costs of \S\ref{sec:discussion}. Most are contracts that exist in some form in beni
today; A3 is new, and A2, A5 and A6 widen existing contracts.

\begin{description}[leftmargin=2.2em,style=sameline,font=\normalfont\bfseries]
\item[A1] \emph{Only licensed writes.} The list runtime writes an array only inside a primitive
declared consumed. No other JavaScript---emitted code, sibling files, platform runtimes---writes a list
it did not just create and still exclusively hold. The array builder used by the backend stays linear.
\item[A2] \emph{Foreign summaries are true.} A borrowed parameter is not kept past the call; a fresh
result is an array nothing else holds; a consumed parameter is written only in the declared way. The
existing promise that a sibling ``never keeps a list it was given'' that it will later write becomes:
a sibling never keeps a list unless its declaration says shared (\S\ref{sec:hard-foreign}).
\item[A3] \emph{The runtime hands the model over.} The platform's entry into \code{update} declares
the model consumed and keeps no content holder of any list of the old model after the arm runs;
anything it needs from the old model it reads before the arm, into locals the checker sees, or as
scalars (\S\ref{sec:hard-tea}).
\item[A4] \emph{Identity holders never conclude ``unchanged'' from identity on a written list.} A
renderer that compares a list by \code{===} to skip work must not do so for a list that may have been
written in place; per-row comparisons must be on the row items, and conditional updates must be
guarded by their own conditions, never by a list's identity.
\item[A5] \emph{Evaluation order is as specified, and a demand is a barrier to the optimiser.} No call
is moved across another or duplicated, every impure call is kept, and no read of a cell---its length,
an element, an offset into a view, a single-use binding folded into its use---is moved across a demand
on that cell. beni's release optimiser today folds a single-use pure binding into its use across other
pure bindings, on the ground that evaluations that make no call cannot be observed in either order:
\code{n = List.length xs; ys = List.push xs 1; h ys n} would become
\code{h(push(xs, 1), xs.length)}. That ground holds only while every list is immutable; the demand
summaries must become an input to the optimiser, as the impure bit already is. \emph{This is a change
to the language definition and the optimiser, not a property of them today.}
\item[A6] \emph{Escapes are total, in both directions.} Every way a value can outlive a frame---a
command or subscription thunk, a spawned fiber, a \code{Ref}, a \code{Queue}, \code{Js.from}, a sibling
parameter not declared borrowed, a stored closure---is a summary that marks the value escaped; and every
value the runtime retains and may hand out again---a fiber's outcome at \code{Task.join}, a bracketed
resource at its release, the results of taking from a queue or awaiting a deferred value---is $\top$ on
every path.
\item[A7] \emph{Continuations are one-shot}, and a cancelled fiber never resumes the rest of its body.
\item[A8] \emph{Asserted core summaries are true}, each pinned by a test program that runs the
emitted JavaScript.
\item[A9] \emph{A defect reads nothing of the program's heap} after it fires, except through escaped
holders. (A development crash screen that printed the model would read a half-updated record.)
\item[A10] \emph{The checker's solved types are the backend's types}: a path is list-typed in the
analysis if and only if the emitted value at that path is an array.
\end{description}

\subsection{What the sketch does not cover}
\label{sec:soundness-gaps}

\begin{itemize}
\item \emph{Path-insensitive joins.} $A(e)$ for a \code{case} is the union of the arms, so a cell held
only on the arm not taken is counted as a holder on the other. This is conservative: more rejections,
never fewer.
\item \emph{The cut and $\top$.} Both lead to rejection by \Known, never to acceptance.
\item \emph{Concurrency.} Fibers interleave only at suspension points. A cell reachable from two
fibers is escaped, because it was captured by a spawned thunk (A6), so no demand on it is accepted.
Within one fiber the sequential argument holds across a suspension, because the continuation holds
exactly the locals liveness already counted, and it runs once (A7).
\item \emph{Defects.} A defect stops the program; its cleanup closures are stored, and therefore
escaped holders. A9 covers what a crash screen may print.
\item \emph{An identity shortcut in list equality} (answering \code{True} at once for
\code{xs == xs}). Such a test can differ between the semantics only when a stale reference meets a
current one, which is a stale dereference and is excluded.
\item \emph{The entry state of \code{update}} is not covered by any caller's side conditions. The
whole-program entry fixpoint of \S\ref{sec:hard-tea} stands in for the caller, and it is where we
would direct a reviewer first, together with A3 and A4.
\end{itemize}

\subsection{Counterexamples to an earlier draft}
\label{sec:soundness-counterexamples}

An adversarial reading of an earlier version of these rules found programs that the rules accepted
although the in-place write was observable, a gap at the entry of \code{update}, and a group of
gaps in the library's contracts. Table~\ref{tab:counterexamples} lists them. Each is now answered by
a rule, and each program is intended to become a test case. What held under the same reading: reads before writes,
dead aliases, per-arm liveness, record-update field replacement, the pessimistic default for
undeclared \code{foreign}s, tail-call argument order, views as holders of their base, the fiber escape
argument, and Lemma~\ref{lem:excl} at the abstract level. We regard this as evidence that the rule set
is checkable, not that it is sound; the report-mode experiment (\S\ref{sec:evaluation}) is the next
test.
