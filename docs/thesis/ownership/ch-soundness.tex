\chapter{Soundness}
\label{sec:soundness}

This chapter states the guarantee and sketches an argument for it. The argument has the shape of
standard proofs for in-place update \citep{aspinall2008usage,bernardy2018linear}, and its lemmas are
the usual ones for a flow analysis; but it is a sketch over an informal semantics of a real
language, it has not been mechanised, and it rests on twelve assumptions about code the checker does
not see (\S\ref{sec:soundness-assumptions}). Short programs are the sharpest test of such rules;
\S\ref{sec:soundness-counterexamples} traces forty-five of them. The evaluation's first experiment
(\S\ref{sec:eval-sanitiser}) is designed to find what the sketch misses.

\section{The claim}

\begin{theorem}[The two semantics coincide]
\label{thm:main}
Let $P$ be a program every module of which the checker accepts: every demand satisfies \Known,
\Unescaped, \Dead\ and \Disjoint\ against the published summaries of its callees; every recursive group
and every group of local functions is validated; no value that may be once reaches an escaping
position that may call it more than once; every type's \code{eq} and \code{compare} only read; and the entry protocol of the platform
that runs $P$ is satisfied. Suppose assumptions A1--A12 hold of the runtime, the core library and the
platforms. Then for every sequence of host events, the value semantics $S_v$ and the update semantics
$S_u$ produce the same \emph{trace}: the same sequence of observations, where an observation is a byte
written to an output stream, a DOM write, a call into a \code{foreign} sibling or a \code{Js} operation
with its arguments marshalled by value, and the program's exit.
\end{theorem}

$S_v$ is beni as it is today, and $S_u$ is what the backend would emit under the rule
(\S\ref{sec:compiler-backend}): writers and constructions write their operand's array. By rule~7 of
\S\ref{sec:bg-language}, $S_u$ is the semantics of the direct platform, and of the test mode in which the
evaluation runs every other program in place (\S\ref{sec:eval-sanitiser}); on a target that keeps
persistent lists, such as the template runtime, $S_u$ \emph{is} $S_v$ and the theorem holds trivially.
The entry protocol in the hypothesis is therefore the direct platform's. The statement
mirrors Aspinall, Hofmann and Kone\v{c}n\'y's soundness theorem, in which in-place evaluation is both
correct and complete with respect to a safe functional evaluation \citep[Thm.~5.8]{aspinall2008usage},
and Linear Haskell's theorem that ``the semantics with in-place mutation is observationally equivalent
to the pure semantics'' \citep[Thm.~3.9]{bernardy2018linear}. We state it over traces rather than final
values because beni's observations are effects at the JavaScript boundary, and because a TEA program
need not terminate.

\section{Instrumented semantics: versions and stale references}
\label{sec:soundness-instrumented}

We add ghost state to $S_u$. Every cell $c$ carries a \emph{version} $\mathit{ver}(c) \in \mathbb{N}$,
incremented by each in-place write; for a once closure, its call is the write. Every reference to $c$,
wherever it is held---a local, a temporary of the normal form holding an evaluated operand, a field of a
structure under construction, an element, a closure environment, a fiber, a runtime structure, a
JavaScript variable---carries the version at which it was created or last obtained from a current
reference: reading a field of a current record yields a current reference, and a binding \code{y = x}
copies $x$'s stamp. A reference is \emph{stale} when its stamp is below $\mathit{ver}(c)$. A
\emph{use} of a reference is a dereference of its elements or length, a call of it, or a comparison of
it by identity.

The correspondence to $S_v$ is a function on references: the reference $(c, k)$ of $S_u$ corresponds to
the array $c_k$ of $S_v$, the $k$th array in the chain $c_0 \to c_1 \to \cdots$ that $S_v$'s edits
built. Contents agree for current references by construction: the write that raised $\mathit{ver}(c)$
from $k$ to $k+1$ in $S_u$ is the new array that made $c_{k+1}$ from $c_k$ in $S_v$, with the same
elements at the same positions. Identity also agrees between current references: two current references
are \code{===} in $S_u$ iff they correspond to the same array in $S_v$, since both have the latest
version. A stale reference $(c, k)$, $k < \mathit{ver}(c)$, may disagree with $c_k$ in contents, and in
identity with the current reference to $c$; those are the only places the two configurations differ.

\begin{lemma}[No stale use]
\label{lem:stale}
If no step of $S_u$ uses a stale reference, the two traces are equal.
\end{lemma}
\begin{proof}[Proof sketch]
By a bisimulation relating configurations that have the same control state with every reference mapped
by $(c, k) \mapsto c_k$. Every step preserves the relation: it uses only current references, whose
contents and mutual identity agree, and the only step that writes---an accepted demand, or the call of
a once closure---produces on both sides a reference whose contents agree ($c_{k+1}$ and $(c, k+1)$). An
observation marshals by value from current references, so it agrees. Identity tests in privileged code
on references the checker does not track are the subject of A4 and A11.
\end{proof}

The theorem therefore reduces to: \emph{in an accepted program, no stale reference is ever used}.

\section{Lemmas}

The lemmas below are stated per point of an execution, and argued by induction on the \emph{length of
the execution prefix}, not on the depth of a call tree: a TEA program dispatches without end, a
recursion may not return, and a callback re-enters frames that are still open. The invariant is over
the whole live configuration---the stack of open frames, every closure, every pending operand and
every runtime structure.

\begin{lemma}[Flow facts over-approximate the heap]
\label{lem:flow}
At every point of an execution, for every open frame, and for every cell $c$ reachable from that
frame's locals and temporaries through a path that some continuation may use---including paths through
closure environments ($\env$), at the captured paths the closure's body uses, and opaque values
($\langle T\rangle$)---there is a holder $(x, q)$ of the frame such that $c$ is named
by a provenance in $A(x)@q$: a site of this frame, the parameter path or environment path it entered by,
$\shared(v)$ for a top-level value $v$, or $\top$; or $c$ is in the frame's $\mathit{Esc}$.
\end{lemma}
\begin{proof}[Proof sketch]
By induction on the prefix, over the transfer rules of Table~\ref{tab:transfer}: each rule's result
contains every cell the construct can produce from its parts, a closure's $\env$ contains every cell
it captured, a top-level value's cells are $\shared$, and a call's result is bounded by the callee's
$\mathit{res}$ (Lemma~\ref{lem:summary}), each provenance translated: $\pi_i.q$ through the arguments,
$\env.q$ through the called closure's environment, a parameter of a callback through $\mathit{supply}$,
$\fresh_k$ to a new site of the call, $\esc_k$ to a new site added to $\mathit{Esc}$, and $\shared$ and
$\top$ to themselves. The cut and the width cap yield $\top$, and every construct without a summary
yields $\top$ and escape. Folding a recursive type maps every path of a value onto a path that exists in
the abstract domain, and an opaque or foreign type that the module cannot see is tracked under its
opaque step, so no cell is hidden behind a type assumed to cross. A closure's run-time environment may
reach more than its abstract $\env$ names---a JavaScript closure keeps the whole \code{model} when its
body reads only \code{model.session}---but a path its body never uses is never followed by any
continuation, so the cells reachable only through it are never used through it, which is all
Lemma~\ref{lem:stale} needs.
\end{proof}

\begin{lemma}[Exclusive contents]
\label{lem:excl}
If a container path carries $\excl$ at a point, then every concrete cell reachable through it is
reachable through exactly one position of the container and one path within that position, and has no
live holder other than the container's path.
\end{lemma}
\begin{proof}[Proof sketch]
By induction on the prefix over the rules of \S\ref{sec:model-excl}. Setting the flag requires each
stored value to be unique at the store and every two stored tracked paths to be disjoint, which is
\Disjoint\ applied within and across stored elements (Lemma~\ref{lem:dead}, reading the store as a
demand that does not write), a dictionary's key and value counting as two paths of one position. A
destructive read overwrites the one position before any other read, and by the induction hypothesis the
element it hands out has disjoint paths and no other holder; the flag survives only when the callback
keeps shape, so every path of what is stored back holds a cell made during the call, held by nothing
else, or the element's own cell at the same path, which by the hypothesis was reachable only through this
position and that path---so conditions 1--3 hold again. A single-pass function is a destructive read of
each position in turn, storing each result at a position of a new array, and the same argument applies
position by position. For a dictionary, the asserted row is the promise that its \code{update} reads no
key that could alias the value it hands out, and keeps the flag on the same condition. A split pattern on
a dead scrutinee hands out one position and keeps the others. Every other store or read clears the flag.
\end{proof}

\begin{lemma}[Liveness over-approximates future uses]
\label{lem:live}
If $\live(h, p)$ is false, then no execution continuing from $p$ uses the cell held by $h$ through $h$.
\end{lemma}
\begin{proof}[Proof sketch]
The uses of \S\ref{sec:model-liveness} cover every construct that can use a value or hand it to
something that can: a direct read; a call, by the callee's summary and Lemma~\ref{lem:summary},
$\unused$ paths excepted; an item of a construction; a return; a store; a capture, by the closure's
$\env$ and the liveness of the closure and of everything that holds it, with a local function's
captures live at each of its calls; a call of a function value; and the catch-all for anything unseen.
Instructions are in evaluation order and every operand is used at its consuming instruction, so ``after
$p$'' is well defined and includes a value held across $p$ and consumed later. A local function's
closure exists from its block's entry, so a call written above its definition is covered.
\end{proof}

\begin{lemma}[Once closures]
\label{lem:once}
A closure the checker did not mark once never writes a cell through its environment. A closure it
marked once is called at most once in any execution---by checked code or by trusted code---and the cells
it may write are reachable, after its creation, only through it.
\end{lemma}
\begin{proof}[Proof sketch]
A closure whose body writes a captured cell, directly or through a call that returns one, calls a
captured once value or passes one to a consuming position is marked once by \S\ref{sec:model-functions};
any other closure writes no captured cell, by Lemma~\ref{lem:summary} applied to its body. A once
closure is an abstract cell whose calls are demands. \emph{Calls in checked code}: by
Lemma~\ref{lem:dead} applied to that cell, the first call finds every other holder of the closure dead,
so no second call happens; a local function's cell exists from its block's entry, and a once local
function does not call itself. \emph{Calls in trusted code}: a once value reaches an escaping position---at
any path of the value that may hold its cell---only where that position's asserted $\mathit{calls}$ is
${\le}1$, such as the body of a spawned fiber or of a command, so no runtime structure, sibling or markup
that may call it again keeps it; a once value passed to a trusted callee is checked against that callee's asserted $\mathit{calls}$, which defaults to $\mathit{many}$, and A2 and A8
say the callee calls it no more often than its row states. Its creation is a demand on the captured cells
it may write, so at creation every other holder of them is dead.
\end{proof}

\begin{lemma}[Summary soundness]
\label{lem:summary}
For every call $f\,\bar a$ evaluated in $S_u$, with argument cells $C_1, \ldots, C_n$:
\begin{enumerate}
\item $f$ writes a cell of $C_i@q$ only if $\mathsf{W} \in \mathit{use}(i, q)$;
\item if $\mathsf{E} \notin \mathit{use}(i, q)$, then after the call no cell of $C_i@q$ is reachable
from any place that outlives the call other than the result, at the paths $\mathit{res}$ names, and
from closures reachable from the result;
\item the result's cells at $q'$ are within $\mathit{res}(q')$ instantiated: $\pi_i.q$ by the argument
cells $C_i@q$, $\env.q$ by the called closure's environment cells, a callback's parameters through
$\mathit{supply}$, $\fresh_k$ and $\esc_k$ by cells allocated during the call, $\shared$ by a top-level
value's cells, and $\top$ by any cell. Distinct numbers name distinct cells. A cell that a result path
names $\fresh_k$ has, when the call returns, no holder that outlives the call other than the result's
paths that name $k$ and closures reachable from them; a cell named $\esc_k$ may in addition be held by an
escaped place;
\item $\mathit{calls}$ bounds the number of calls $f$ makes to argument $j$, and $\mathit{supply}$ bounds
what $f$ passes to it; if $\mathit{xres}(q')$, the result's container at $q'$ is exclusive; if
$\mathit{xreq}(i, q)$ is not set, $f$ relies on no exclusivity of $C_i@q$.
\end{enumerate}
\end{lemma}
\begin{proof}[Proof sketch]
By induction on the length of the execution prefix, with the call's clauses established when the call
returns and assumed for every call that returned earlier in the prefix. For a non-recursive $f$, the
summary was read off its body under Lemmas~\ref{lem:flow} and~\ref{lem:live} using its callees'
summaries, which hold by the induction hypothesis for every callee call that has returned. Clause~3 is
what the read-off rule of \S\ref{sec:inf-summarise} establishes: values are immutable, so a cell made
during the call can be held after it only by the result, by a closure or structure reachable from the
result, or by a place the walk put in $\mathit{Esc}$---which the rule names $\esc_k$; the frame's locals
are dead at return; and a cell the body did not make is named by where it came from, never $\fresh$. For
a recursive group, the validated fixpoint is a consistent assignment: each body checks against the final
summaries, so the hypothesis for the recursive calls is exactly the summary, and the body's own analysis
yields the summary again. The optimistic start does not weaken the argument, because only the validated
assignment is used. For a \code{foreign} or an asserted summary, the summary is declared and the
implementation is trusted (A2, A8). A call that never returns needs only clauses~1 and~4, which hold of
every prefix.
\end{proof}

\begin{lemma}[Dead aliases]
\label{lem:dead}
At an accepted demand $u$ on cell $c$, every reference to $c$ other than the one the demand consumes is
dead: it is never used afterwards, by the caller, by any frame below it, by any closure, pending
operand or structure, or by the callee during the call.
\end{lemma}
\begin{proof}[Proof sketch]
By \Known\ the cell is known. By \Unescaped\ it is neither escaped nor shared, so (Lemma~\ref{lem:flow})
every reference to it is accounted for by a holder of the current frame---a local, a temporary, a
structure or literal under construction, a path through a closure's $\env$, including the environment of
a local function whose block is open---or of a caller's frame through the chain of parameters and
environments. By \Dead\ each local holder is dead after the demand (Lemma~\ref{lem:live}). By \Disjoint\
no other operand path---including another path of the same argument and the other items of a
construction---and no cell under $\env$ of a function-valued argument holds $c$, so nothing the callee
reads during the call reaches $c$; the callee's own locals that hold $c$ are aliases of its written
parameter and are checked by the callee's own side conditions with the parameter as operand. Each
parameter-path holder was checked at the caller's call site, where the same conditions applied to the
caller's holders, by clause~1 of Lemma~\ref{lem:summary}; an environment-path holder was checked at the
creation of the once closure that consumes it (Lemma~\ref{lem:once}); when the caller is a container
function supplying an owned element, the conditions are supplied by Lemma~\ref{lem:excl}; when the caller
is the platform, by Lemma~\ref{lem:entry}.
\end{proof}

\begin{lemma}[Entry]
\label{lem:entry}
On the direct platform, if it keeps its entry protocol (A3, A4, A12), every dispatch calls \code{update}
with a model whose written paths satisfy \Unescaped, \Dead\ and \Disjoint, and are exclusive where an arm
requires it, as a caller would have to establish; and every message payload an arm writes in place is
unique when the arm runs.
\end{lemma}
\begin{proof}[Proof sketch]
The protocol models the platform's loop---the model is \code{init}'s result, then each dispatch's
result---as a recursive caller of \code{update} with an asserted row (\S\ref{sec:hard-tea}), instantiated
at the program constructor's call with the program's own functions. Its abstract model is the least
fixpoint of \code{init}'s and \code{update}'s summaries. By clauses~2 and~3 of Lemma~\ref{lem:summary}
every escape that \code{init}, any arm, any command body or any subscription creates appears in it:
an escape of a cell the call received as $\mathsf{E}$ on a parameter path, an escape of a cell the call
made as $\esc_k$, a top-level list as $\shared$, and a value the runtime retains as $\top$. \code{view}
creates none: by \Obl{P3} no value one evaluation of it made---a handler, a message, a markup value---is
used after a dispatch that conflicts with what it read, and a listener body reads the model current at
its event; so a cell of the model that \code{view} read is not used through anything \code{view} made
once a later arm may have written it. Aliasing between model paths appears through numbered fresh cells,
and exclusivity through $\mathit{xres}$, carried round the fixpoint by clause~4. The check at the
constructor's call rejects a written path that may alias another, or whose cells may be escaped, shared
or unknown, or that an arm needs exclusive and the fixpoint does not find so. A payload reaches the arm
from a view event, which \Obl{P6} treats as aliased with the model, or from a \code{send}; the entry
fixpoint follows each send site's payload through \code{update}'s results to every model path it may
reach, and a send whose payload may reach a path written in place was checked as a demand at the send,
so the payload is unique when the arm that writes it runs, however many dispatches later. \code{init} is
a function the platform calls once per mount, so the first model of every mount has the cells its
summary describes. A3 says the runtime holds nothing else as a content holder; A4, with A12, that no
identity test of the renderer concludes ``unchanged'' about a value that may hold a cell written in place
by the current dispatch.
\end{proof}

\begin{proof}[Proof sketch of Theorem~\ref{thm:main}]
By induction on the prefix. At each accepted demand, Lemma~\ref{lem:dead} says every reference to the
written cell other than the one consumed is dead, hence never used again, and the returned reference is
current. So no step uses a stale reference, which is the hypothesis of Lemma~\ref{lem:stale}.
\end{proof}

\section{Assumptions}
\label{sec:soundness-assumptions}

The theorem is conditional on the following assumptions about code the checker does not analyse. A
false assumption produces a wrong answer, not a false error, which is why we list them here rather
than among the costs of Chapter~\ref{sec:discussion}. After each we say where it is kept, or must be.

\begin{description}[leftmargin=2.2em,style=sameline,font=\normalfont\bfseries]
\item[A1] \emph{Only licensed writes, and no stale cache.} The list runtime writes an array only inside
a primitive whose row says written, or a construction's base. No other JavaScript---emitted code, sibling
files, platform runtimes---writes a list it did not just create and still exclusively hold. The array
builder stays linear. Every cached derived form of a cell---a view's cached plain copy, a stored
length---lives in a header that a licensed write consumes and replaces: a write through a view, a
prepend into headroom included, returns a new header and never leaves a live header whose cached fields
describe the old version. \emph{Kept by} the list runtime's existing invariant that it writes only
arrays it has just made, restated; with the trie gone, the exceptions for claimed head and tail slots
disappear.
\item[A2] \emph{Foreign summaries are true.} A read parameter is not kept past the call; a fresh result
is an array nothing else holds; a written parameter is written only in the declared way; a function-typed
parameter is called no more often than the row's $\mathit{calls}$, which defaults to $\mathit{many}$.
\emph{Kept by} the boundary contract (\S\ref{sec:bg-boundary}), widened: the existing promise that a
sibling never writes a list it was given and never keeps one it will later write becomes: a sibling never
keeps a list unless its row says escaped (\S\ref{sec:hard-foreign}).
\item[A3] \emph{The platform keeps its entry protocol.} For every function the direct platform calls on
the program's behalf, it passes and keeps exactly what the protocol of \S\ref{sec:hard-tea} says:
\code{init} is called once per mount; after an \code{update}, the runtime holds no content reference to
any list of the old model; it reads the model for the view's sites, \code{settle}, derived values and
listener bodies without keeping a content reference beyond what the protocol declares, and uses nothing
an earlier evaluation of the view made after a dispatch that conflicts with it; and it runs command bodies
and keeps subscription results as declared. \emph{Kept by} the direct platform's design, made precise as
obligations \Obl{P1}--\Obl{P7}, which must be written into its specification before it writes any list in
place. A target that keeps persistent lists, the template runtime among them, needs none of this.
\item[A4] \emph{No identity test concludes ``unchanged'' about a value that may hold a cell written in
place.} In the direct platform's handler for a key $\kappa$, no \code{===} test and no comparison of views
by base and offset concludes ``unchanged, skip'' about a value that may hold a cell at a path of
$\mathit{IP}_\kappa$; everything that reads such a value runs because the key's write set conflicts with
its read paths (\Obl{P7}). \emph{Kept by} the direct platform's groups, derived values, branches and row
inputs as designed, and by the changes \Obl{P7}(f) and (g) make to its element-guarded scripts, which are
not yet in its specification. On the template runtime, which skips by identity everywhere, it holds
because no list is written in place there (rule~7).
\item[A5] \emph{Evaluation order is as specified, and a demand is a barrier to the optimiser.} No call
is moved across another or duplicated, every impure call is kept, and no read of a cell---its length,
an element, an offset into a view---is moved across a demand on that cell, whether by single-use
folding or by the freedom to order call-free evaluations. Today the optimiser folds a read of a beni
value into a statement whose earlier operands make calls, and a list's length and element reads are
such reads after lowering (\S\ref{sec:bg-release}): \code{n = List.length xs; h [ …xs, 1 ] n}
may become \code{h(push(xs, 1), xs.length)}. The demand summaries must become an input to the optimiser,
as the impure bit already is, and the language definition's statement that call-free evaluations may be
ordered freely must exclude a read of a cell across a demand on it. \emph{This is a change to the
language definition and the optimiser, not a property of them today.}
\item[A6] \emph{Escapes are total, in both directions.} Every way a value can outlive a frame---a command
or subscription body, a spawned fiber, a \code{Ref}, \code{Js.from}, a sibling parameter not declared
read-only, a stored closure, a handler or message in markup, a runtime structure---is a row that puts
$\mathsf{E}$ on it; every constructor of a foreign type's values has such a row; and every value the
runtime retains and may hand out again---a fiber's outcome at \code{Task.join}, a bracketed resource at
its release, a deferred value's contents---is $\top$ on every path. \emph{Kept by} the asserted rows of
the core \code{Task} module, the markup lowering and the platforms.
\item[A7] \emph{Continuations are one-shot}, and a cancelled fiber never resumes the rest of its body.
\emph{Kept by} the fiber runtime's existing contract (\S\ref{sec:bg-effects}).
\item[A8] \emph{Asserted summaries are true}, each pinned by a test program that runs the emitted
JavaScript under the differential run of \S\ref{sec:eval-sanitiser}. This covers the whole trusted
surface of \S\ref{sec:soundness-trusted}, not only the writers.
\item[A9] \emph{A defect reads nothing of the program's heap} after it fires, except through escaped
holders. (A development crash screen that printed the model would read a half-updated record.) To be
checked for the development crash screen.
\item[A10] \emph{The checker's types are the backend's types}: a path is tracked in the analysis if and
only if the emitted value at that path may be an array or a closure, or is of a type the analysing
module cannot see into; a foreign type is declared crossing only if none of its values holds a list or a
closure.
\item[A11] \emph{Identity tests in privileged code are covered.} Every \code{===} that core or a
platform performs on a list either is on two current references, or its outcome cannot reach a trace
observation, or both outcomes are covered by the function's summary---so that the result named in
$\mathit{res}$ is right whichever branch is taken. \emph{Kept by} the identity promises appearing in
their functions' $\mathit{res}$ as both outcomes (\S\ref{sec:model-demands}), and by A4 for renderers; the
remaining tests are listed with the trusted surface. One such test compares a reference that an in-place
write has made stale: \code{map}'s check that a callback returned its element itself, after a callback
that was supplied the element owned may have written it. Its outcome only chooses between returning the
input array and returning the new one, whose contents are then the same, and $\mathit{res}$ names both.
\item[A12] \emph{The write set names every in-place write.} For every message key, every model path that
an accepted demand of the key's arm may write in place is named by the key's write set---a path the set
conflicts with. The write-set analysis states its soundness over identity (``changed'' is ``not
\code{===}''), which an in-place write does not change, so this is not a consequence of its statement;
it is a fact about its rules, which interpret every writer and every construction through the core
library's table as a write of the path it edits, whatever object results. \emph{Kept by} restating the
write-set contract over contents---``changed'' becomes ``may differ in content from before the
dispatch''---and checking it (\S\ref{sec:compiler-writesets}); the direct platform's verification mode
and its differential fuzzing are the run-time checks of it.
\end{description}

\section{The trusted surface}
\label{sec:soundness-trusted}

Demands are carried by a small set of primitives, but much more is trusted. Inference sees through beni
code, but much of the core library is beni over the \code{Js} interface or calls \code{foreign}
primitives, and by the transfer rules every such call reads and escapes its arguments and returns
$\top$. Without an asserted row, every list passed to \code{List.map}, \code{String.join} or
\code{Debug.log} would be escaped for the rest of the program. The trusted surface is therefore every
function in the core library or a platform whose body goes through \code{Js} or a \code{foreign} and
handles a cell. Counted from the sources as they stand---public values as declarations beginning
\code{pub} followed by a value's name and type, \code{foreign} declarations by their keyword, and
low-level computations as occurrences of \code{Js.pure} outside comments:
\begin{itemize}
\item \emph{the list module} (49 public values, 7 \code{foreign} declarations, 17 \code{Js.pure}
computations): the nine writers and \code{copy}; the primitives that constructions lower to; the
internal primitives the library's loops are written over (the element read, the base array and offset of
a list, the builder and its fill and hand-over, the building loop's exit, the length); the identity
primitives \code{map} uses to return its input; the single-pass rows of \code{map}, \code{indexedMap},
\code{filterMap}, \code{foldl} and \code{foldr}, which supply an element owned when the list is exclusive and
consumed; and every public function whose body uses \code{Js} directly rather than those primitives;
\item \emph{strings} (45 public values, 21 \code{Js.pure} computations): every function that takes or
returns a list, such as joining and splitting, which must say that it reads its list or returns a fresh
one;
\item \emph{debugging} (5 public values over \code{Js}): \code{Debug.log} returns its second argument
and only reads it; \code{Debug.toString} only reads;
\item \emph{tasks, mutable cells and deferred values} (50, 5 and 5 public values; 5 \code{foreign}
declarations in the task module): \code{spawn}, \code{join}, \code{scope}, \code{bracket}, \code{Ref.get},
\code{Ref.set}, \code{Ref.update} and their kin, whose rows carry the escapes and call counts of A2 and A6;
\item \emph{schemas} (42 public values, 7 \code{foreign} declarations): a parser's output is fresh, and
exclusive by declaration, or not; a printer only reads---unless it hands a list's array to the host as it
is, in which case it escapes it;
\item \emph{the dictionary and set modules} are beni over constructors with no \code{Js}; their summaries
are inferred over folded paths, and only \code{Dict.update}'s row---its owned supply to its callback and the
exclusivity of its result---is asserted (\S\ref{sec:hard-containers});
\item \emph{each platform}: its \code{foreign} siblings and foreign types; for the direct platform, its
entry protocol (\Obl{P1}--\Obl{P7}); its commands and subscriptions, \code{send}, and its markup lowering, whose rows
say what a markup site keeps;
\item \emph{the runtime contracts}: A1, A3, A4, A7, A9, A11 and A12.
\end{itemize}
We have not yet enumerated the rows one by one; doing so, with a test program per row under A8, is the
first deliverable of the report mode (\S\ref{sec:eval-brief}). We expect between several dozen and a
hundred and fifty asserted rows, the upper figure being every public function of the modules above that
handles a list. The surface is the same kind as the effect rungs the compiler already trusts---a false
row is a bug in privileged code---but it is several times larger than the writers, and it is where an
implementation is most likely to be wrong.

\section{What the sketch does not cover}
\label{sec:soundness-gaps}

\begin{itemize}
\item \emph{Monotonicity}, case by case (\S\ref{sec:inf-lattice}); it is asserted, not written out.
\item \emph{Path-insensitive joins.} $A(e)$ for a \code{case} is the union of the arms, so a cell held
only on the arm not taken is counted as a holder on the other. This is conservative: more rejections,
never fewer.
\item \emph{The cut, folding and $\top$.} All lead to rejection by \Known\ or \Dead, never to acceptance.
\item \emph{Concurrency.} Fibers interleave only at suspension points. A cell reachable from two
fibers is escaped, because it was captured by a spawned body (A6), so no demand on it is accepted.
Within one fiber the sequential argument holds across a suspension, because the continuation holds
exactly the locals liveness already counted, and it runs once (A7). Nothing in the argument depends on
when a command's body runs relative to later messages: a command's captures are escaped.
\item \emph{Defects.} A defect stops the program; its cleanup closures are stored, and therefore
escaped holders. A9 covers what a crash screen may print.
\item \emph{An identity shortcut in list equality} (answering \code{True} at once for
\code{xs == xs}) compares two references. If both are current, the semantics agree; if one is stale,
the comparison is a stale use, which Lemma~\ref{lem:dead} excludes.
\item \emph{The trusted surface}, whose rows are not yet enumerated (\S\ref{sec:soundness-trusted}).
\item \emph{The entry protocol}, which is only as good as the direct platform's keeping of A3, A4 and A12.
\Obl{P7}(f) and (g) and \Obl{P3}'s rule for markup values are additions to its design, not yet specified,
and A12 restates the write-set analysis's contract over contents, which its own soundness argument does not
yet cover.
\end{itemize}
