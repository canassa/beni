\chapter{Evaluation Plan}
\label{sec:evaluation}

The design's soundness can be argued at a desk, and the short programs of
Table~\ref{tab:counterexamples} show how easily such an argument misses a case. Its value cannot be argued
at a desk at all. Whether the rule is worth adopting depends on whether it is sound in practice and, above
all, on \emph{how often idiomatic code meets the error}: with construction consuming its base, nearly every
list-building idiom is a demand, and a rule that rejected a noticeable share of them would be unusable
however sound. We know of no published false-error rate for an inferred uniqueness checker in a functional
language. This chapter describes the experiments we propose to run before deciding. \emph{None has been
run, and we report no results.}

The experiments follow the path by which beni's write-set analysis was introduced
(\S\ref{sec:bg-browser}): build the analysis, run it as a report over real programs, classify every
rejection, and decide on the numbers---here, against criteria written down before the run. Following
Wrenn and Krishnamurthi's view of errors as classifiers \citep[\S2]{wrenn2017classifiers}, the experiment
measures the precision of the classifier the checker would be.

\section{The next phase: a prototype checker and a differential soundness test}
\label{sec:eval-next}

This is the last form of the design to be argued on paper. Four rounds of adversarial reading each found
accepted programs whose in-place run would differ from their value run---nine such holes in the last two
rounds alone---and every one was at an \emph{interaction}: a fold's asserted row and a top-level value; an
opaque type and a caller's \Disjoint; a recursive type's folding and liveness; a send and an arm that
edits a payload without storing it; the release representation and the renderer's identity guards. Each
rule was right on its own, and each repair was local. A fifth reading would likely find more of the same
kind, more slowly, because the combinations grow faster than a reader can trace them. The next phase
therefore replaces reading with testing.
\begin{enumerate}
\item \emph{A prototype checker in report mode} (\S\ref{sec:eval-report}): the analysis of
Chapters~\ref{sec:model}--\ref{sec:hard} as a pass that prints its verdicts and changes no emitted byte,
with the trusted surface enumerated row by row as it is needed.
\item \emph{A differential soundness test.} Every program the prototype accepts is run under both
semantics: the value semantics, and the in-place backend with the stale-read sanitiser
(\S\ref{sec:eval-sanitiser}), whose every list carries a version and every reference the version it was
obtained at, so that any read of a stale list traps with its origin and the write that made it stale. The
traces must agree and nothing may trap.
\item \emph{Three sources of programs.} The compiler's test corpus, including the programs that run in a
page; the applications (TodoMVC, Conduit, the table benchmark); and \emph{randomly generated programs}
that combine the features whose interactions broke earlier forms of the rules. A generator draws a small
well-typed program from a grammar of list idioms---folds and maps with callbacks of every class,
top-level values, closures that capture and are stored, spreads and \code{++} chains, records, tuples and
constructors, dictionaries, opaque types declared in a second module, recursive types, commands that
capture and send, \code{update} arms that store and edit---and crosses them systematically: folds with
top-level values and captures, captures with spreads, containers with callbacks that return what they did
not make, opaque and recursive types with every demand, and every program built twice, in a development
and a release build. Each generated program the prototype accepts goes through the differential test; each
it rejects is kept as a measure of precision. A program that traps is shrunk to a minimal one, added to
Table~\ref{tab:counterexamples}, and the rule it exposes is repaired before anything else proceeds.
\end{enumerate}
Generated programs test what the corpus cannot: the corpus contains only the combinations someone wrote,
and the holes so far were in combinations no one had. They do not prove anything either. What they buy is
a search that is cheap to run often and grows with the rules, where a reading is expensive and stops at
the reader. The decision criteria below are applied only after this phase finds no trap over a budget of
generated programs fixed in advance.

\section{The differential run that traps stale reads}
\label{sec:eval-sanitiser}

The first experiment runs every program the checker accepts under both semantics. We build, in a test
mode only:
\begin{itemize}
\item \emph{an in-place backend}: the list runtime of Table~\ref{tab:backend}, with every accepted demand
written in place---constructions included---and every once closure's call counted. It is what the direct
platform ships; the test mode also links it into programs built for Node, which has no renderer, since the
theorem is about the rules and not about one platform. It is \emph{not} linked into the template runtime:
that runtime skips work by identity everywhere and is outside $S_u$ by rule~7, so an in-place run there
would differ from the value run on accepted programs---TodoMVC's \code{hidden} attribute among them---and
make the first decision fire on programs that are correct;
\item \emph{a stale-read sanitiser}: the instrumented semantics of \S\ref{sec:soundness-instrumented}
made executable. Every array carries a version counter, incremented by each in-place write; every
reference to an array that the emitted code creates---a local, a field, an element, a closure's
environment, a pending operand, a runtime structure---is wrapped with the version at which it was
obtained, and every dereference, identity comparison or call through a stale wrapper \emph{traps},
printing the reference's origin and the write that made it stale. A second call of a once closure traps
the same way;
\item \emph{a shadow mode}, for the template runtime and every other target that keeps persistent lists:
the persistent runtime, unchanged, with each accepted demand marking the array it consumed as
\emph{superseded}, and every later read of a superseded array by program code trapping. A superseded array
is one the in-place run would have overwritten, so a read of it is exactly a stale use, found without
writing anything in place. The runtime's own identity holds are exempt, since on these targets they are
sound.
\end{itemize}
Every accepted program of every corpus below is then run three times on Node and on the direct
platform---under value semantics, under the in-place backend, and under the in-place backend with the
sanitiser---and once more under the shadow mode on the template runtime. The first two runs must print the
same trace, and neither the sanitiser nor the shadow mode may trap. beni's compiler already records, per test program, a hash of
its emitted output and its expected result, and skips re-running programs whose hash matches; the
differential run reuses that machinery, so it costs one extra run per changed program.

The sanitiser is stronger than the trace comparison: it fires on a stale read that happens not to change
the output. It also tests the trusted surface---a wrong asserted row shows up as a trap in the row's
pinned test program (A8)---and the entry protocol, since browser programs are driven by scripted events in
the compiler's test programs that run in a page. It cannot test what the corpora do not exercise, so every
program of Table~\ref{tab:counterexamples}, and one program per transfer rule and per side condition, joins
the corpus, written to fail before the rule that rejects it exists.

\section{Report mode}
\label{sec:eval-report}

The analysis is built first as a pass that only reports. It runs during checking, prints a dump---for
instance under \code{beni dump --stage=ownership}---and changes no emitted byte, so no test program's
output or recorded hash moves; nothing reads the dump but people and tests. The dump prints, per module:
\begin{Verbatim}
summary <Decl>
  param <i>.<path> <unused|R|RA|RE|RW|⋯> [reason <tag>]
  result <path> {<param paths>|fresh<k>|esc<k>|env<path>|shared|top} [excl]
  fun <j> calls <0|1|many> supply <k> <owned|borrowed> {<provenance>}
demand <Decl>:<inst> <writer|construction> operand <cells> idiom <I1..I7|other> [position]
  unique                                               -- accepted
  shared <holder> kept-at <inst> used-at <inst> exact  -- real sharing
  shared <holder> ⋯ approx <limit-tag>                 -- possible sharing (a limit)
  unknown <limit-tag>                                  -- Known or Unescaped failed
once <Decl>:<inst> created | called-twice-at <inst> | passed-to-many <callee> | escapes
copy <Decl>:<inst> of-unique                           -- a copy of a list already unique
entry <program> path <path>
  <owned|aliased-with <path>|escaped by <arm>|shared|unknown>
cap <which> fired at <Decl>
\end{Verbatim}
The idiom of a demand is assigned by a syntactic classifier written before the run---a construction or
writer whose operand is a parameter rebound by a tail call is I1, one in a callback passed to a fold is I2,
and so on, following \S\ref{sec:idioms-list}---and a person checks the classifier's output on a sample. The
classifier only \emph{labels}: it does not decide which demands count as idiomatic (\S\ref{sec:eval-counts}).
A rejection caused by the position rule's choice of base is marked \code{position}. The entry check is
reported under the direct platform's row, the only one the checker uses; the row is a declaration, so the
report mode can evaluate a program under it although the direct platform's in-place slice does not yet
exist. The dump is deterministic (\S\ref{sec:inf-modular}), is
compared byte for byte by the determinism test, and is itself tested against expected output for a set of
small programs, one per transfer rule and per side condition.

\section{Corpora}
\label{sec:eval-corpora}

The corpora we have are biased. beni's core library and the compiler's test programs were written by the
compiler's authors, partly to exercise the very edit scripts the rule would help. We therefore run over
five corpora and report each separately:
\begin{enumerate}
\item the core library;
\item the compiler's test programs: those that run under Node, those that run in a page, and the
write-set analysis's own tests;
\item TodoMVC (five programs) and Conduit, as written and with the changes of \S\ref{sec:disc-apps}
counted;
\item a table-rendering benchmark application on the direct platform;
\item an \emph{external} corpus: open-source Elm applications, chosen before the run by a stated rule
(for example the most-starred Elm applications above a size threshold), ported to beni. The port is
mechanical in part---beni's formatter migrates syntax, turning \code{x :: acc} into \code{[ x, …acc ]}---and
by hand in part, since beni has no automatic currying and \code{init} becomes a function; we count the
porting effort, and port without regard to the rule, writing each list operation the way an Elm
programmer wrote it, and building each for the direct platform.
\end{enumerate}
The external corpus is the one the decision rests on, because it was not written with the rule in mind.
Its demands are idiomatic by definition: they are what Elm programmers wrote, carried over. The idioms
I1--I7 of Chapter~\ref{sec:idioms} were drawn from forms we knew to pass, so they are a way of breaking the
result down, not the definition of the population it is measured on.

\section{Hand classification}
\label{sec:eval-hand}

Every exact rejection is read by a person and classified as \emph{intended sharing} (the program keeps a
version on purpose: an undo, a snapshot), \emph{accidental sharing} (the program would have been wrong had
the write been in place---the bug class the rule exists to catch), or \emph{avoidable} (a reordering, a
fold or a reading form would make the operand unique), and by the idiom it occurs in. Every approximate
rejection is classified by whether a known extension---a discipline for mutable cells, a deeper path cut, a
path-sensitive join, a summary on a platform \code{foreign}, a summary split by message
constructor---or a library choice---commands that take values, messages that carry identifiers---would
accept it. The model is Cann, Feo and DeBoni's report on the Sisal compiler, whose compilation statistics
count copy operations in five application programs before and after optimisation---293 before, none
unconditional and 29 conditional after---and whose prose attributes each remaining conditional copy to row
sharing \citep[Table~I]{cann1990sisal}; our classification adds by hand the step their table leaves to
prose.

\section{People}
\label{sec:eval-people}

Rejection rates measure the checker, not the cost to the programmer of living with it. Crichton et al.'s
studies of Rust learners show that predicting a rejection and fixing it are different skills
\citep{crichton2023grounded}. We propose a small study alongside the counts: give programmers who know
beni but not the rule a sample of rejected programs from the external corpus, with the messages of
Chapter~\ref{sec:errors}, and record whether they fix each, how, and how long it takes---in particular,
whether they reach for \code{List.copy}, for a reading form, for a reordering or for computing a value
before a command, whether they understand which operand a construction reuses, and whether they can tell
an exact rejection from an approximate one from the verdict line.

\section{Decision criteria, fixed in advance}
\label{sec:eval-decisions}

The numbers inform four decisions, in this order, against criteria we state now so that an outcome can
refute the proposal. The decision rests on the external corpus, built for the direct platform and checked
against its entry row, the only one the checker uses. Rates are computed pooled over all applications, and
must also hold for the median application; the decision needs at least 500 demand sites from at least ten
applications, and if the corpus yields fewer, it is enlarged by the same selection rule before anything is
decided. Every demand site of the external corpus counts: the corpus is idiomatic by definition, and no
classifier removes a site from it.
\begin{enumerate}
\item \emph{Soundness.} If the differential run traps on any accepted program, or the two traces differ,
on any corpus or on any generated program of \S\ref{sec:eval-next}, the rule is not adopted until the cause
is found, the rule is repaired, and a test pins it. No rate of traps is acceptable.
\item \emph{Adoption.} The rule is adopted only if (a) fewer than one in fifty demand sites of the external
corpus is rejected, rejections caused by the position rule included; (b) no idiom I1--I7 has a rejection
rate above one in fifty on its own, so that no common idiom carries the errors the others do not;
(c) fewer than half of the rejections are approximate, under the tags of Table~\ref{tab:tags}, which count the
abstraction's own merges as approximate; and (d) in the study of \S\ref{sec:eval-people}, most rejections
are fixed within a few minutes. Otherwise the in-place representation is not adopted yet: today's
persistent \code{List} stays on every target, the most frequent tags and idioms are addressed---by the
checker, the library or the platforms---and the experiment is run again. There is no shipped form in which
the compiler copies where it would reject.
\item \emph{The renderer.} The direct platform writes lists in place only if, with \Obl{P7} met, its pages
keep the targets its design sets---against hand-written JavaScript and against the reference renderer,
quoted as per-operation medians---on its table page, on TodoMVC, and on a page whose list elements are lists
edited in place (a grid, and a board of columns edited by \code{map}), with the rows that \Obl{P7}(f) and (g)
make run included.
\item \emph{Which extensions to build,} on the frequency of each approximate tag: a path-sensitive join
only if the join tag is above a twentieth of rejections, a discipline for mutable cells only if the
\code{Ref} tag is, summaries split by message constructor only if the view-event tag is, a relational entry
only if the entry-merge and kept-copy tags together are, dropping the identity promises (O2) only if the
kept-copy and splice tags together are and a relational entry would not remove them, the split of a
recursive value by a pattern only if the fold tag is, a special case for a one-element \code{map} only if the
$\mathit{calls} = \mathit{many}$ tag is, and value-taking command constructors if the command tag is above a
twentieth of rejections.
\end{enumerate}
The thresholds are our judgement, not derived; they are written down so that the decision cannot be
fitted to the outcome. Rejections caused by a top-level model count in criterion 2(a) like every other
position rejection, and are reported on their own line beside it: the port of an Elm program makes
\code{init} a function and leaves \code{initialModel} as it was written, so that the criterion is neither
met nor failed by the porting rule. The error rate on the other targets, where the rule buys nothing but portability,
is reported beside these and does not enter them. Whether to add the in-place forms of proposal O1 is
decided separately, on how often the external corpus's \code{map}, \code{filter} and sorts are applied to a
list that is unique and dead at the call.

\section{What an implementation must provide}
\label{sec:eval-brief}

For the experiments to be run, an implementation must provide, in this order: the enumerated trusted
surface of \S\ref{sec:soundness-trusted}, one asserted row and one pinned test program at a time; the
in-place backend, the sanitiser and the shadow mode of \S\ref{sec:eval-sanitiser}, in a test mode; the
program generator of \S\ref{sec:eval-next}, with its shrinker; the dump format above,
with the idiom classifier; the direct platform's entry protocol as an asserted row on its program
constructors; the derivation tags of \S\ref{sec:errors-tags}; one test program per
transfer rule of Table~\ref{tab:transfer}, per summary rule of \S\ref{sec:inf-summarise} and per row of
Table~\ref{tab:counterexamples}, each written to fail before the rule exists; the determinism test's
comparison of the dump; a profiling event for the pass; and the hand-classification sheet. No emitted byte
changes outside the test mode. The pass is to be specified as a normative part of the compiler's design
before it is built; this thesis is the argument for that specification, not the specification itself.

\section{Performance, afterwards}
\label{sec:eval-perf}

If the rule is adopted, a second experiment repeats the prototype study's benchmarks
(\S\ref{sec:bg-measure}) with the trie removed and lists written in place---the static variant's
numbers, without its fallback---together with page-size measurements, the direct platform's table
benchmarks and their sweeps, the cost of prepending with room in front under the policies of proposal O3,
and the cost of \Obl{P7} on the direct platform, on a page whose list elements are lists edited in place,
which none of its current benchmark pages exercises. The prototype study gives the expected shape:
large gains when building in a fold and on steady grid ticks, gains hidden by the render walk on TEA table
messages, and nothing for histories, which must copy. That expectation is to be measured, not assumed.
