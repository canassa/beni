\section{TodoMVC's new todo}
\label{app:todomvc}

The application's own code, abridged:
\begin{Verbatim}
init : Model × Cmd Msg
init = ⋯                                   -- a value today; a function under the rules
KeyDown event → ⋯
    changed { model | draft = "", nextId = model.nextId + 1 }
            (model.todos ++ [ { id = model.nextId, title = title, completed = False } ])
Toggle id → changed model (List.map model.todos λt → if t.id == id then { t | completed = not t.completed } else t)
changed model todos = ( { model | todos = todos }, save todos )
save todos = Cmd.do λ⊤ → saved (Storage.set Local key (encode todos))
\end{Verbatim}

\paragraph{The demand.} \code{model.todos ++ [ ⋯ ]} consumes \code{model.todos}, its left operand, and reads
the literal. Evaluation order puts the first argument of \code{changed}---a record that still holds the old
\code{todos}---before the construction, so that record is a pending holder at the demand. It is not a use:
\code{changed}'s summary is $\unused$ at $\pi_1.\mathit{todos}$, because its record update replaces that
field, and $\mathit{res}(.1.\mathit{todos}) = \{\pi_2\}$. The arm's other holders of the cell are
$(\mathit{model}, .\mathit{todos})$, which is dead after the arm. Locally the demand passes.

\paragraph{The entry.} At the program constructor, the entry fixpoint asks what \code{model.todos} may hold
at any dispatch. \code{init}, once it is a function, decodes the stored list or starts from \code{[]}: fresh.
But every arm that changes the list calls \code{save}, whose command captures the arm's new list; the
capture puts that cell in $\mathit{Esc}$, so \code{update}'s $\mathit{res}(.1.\mathit{todos})$ contains
$\esc_k$ for the arms that build with \code{map} and \code{filter}, and $\mathit{use}(\pi_2.\mathit{todos})$
contains $\mathsf{E}$ for the arm that appends. At every later entry the path is escaped, and the append
fails \Unescaped: \emph{rejected}, as possible sharing, on every platform. With \code{save} encoding before
the command, \code{todos} is only read, nothing escapes, and the entry finds the path fresh at every entry.

\paragraph{The renderer.} \code{view} renders \code{List.filter model.todos (visible model.filter \_)},
which by the identity promise may be \code{model.todos} itself. On the template runtime as it stands, that
\code{<For>} skips its walk when it receives the same list, so the entry row treats the path as escaped and
the append is \emph{rejected}. Under \Obl{P7}, the lowering learns from \code{update}'s summary that
\code{model.todos} is written in place, compiles that \code{<For>} without the skip, and the append is
\emph{accepted}: on the base array it is \code{a.push(v)}. On the direct platform it is accepted by
construction of the platform.

\section{A table application's row swap}

\begin{Verbatim}
SwapRows → { model | rows = List.swap model.rows 1 998 }
\end{Verbatim}
On the direct platform, with \code{init} a function. \code{swap} is a writer. The holders of
$(\mathit{model}, .\mathit{rows})$'s cell are that path itself and the runtime's instance array, which holds
items for identity comparison only (A4); no arm captures \code{rows} in a command, and no path of the model
aliases it, so the entry protocol finds it owned. The model is dead after the arm. \emph{Accepted}: two
assignments on the plain array. The platform's edit script compares row items, never the list's identity.
In the persistent representation the same message performs two \code{set}s, each a path copy through the
trie at that size, and a spread of the model record; in place, the swap is two array writes.

\section{A histogram by fold}

\begin{Verbatim}
hist = List.foldl samples (List.repeat 0 1000) (λs acc → List.update acc (bucket s) (λn → n + 1))
\end{Verbatim}
\code{repeat}'s result is fresh. \code{foldl}'s class supplies its callback a borrowed element and an
owned accumulator (provenance $\pi_2$ and the callback's own previous result), calls it many times, and
keeps none of it. In the lambda, \code{List.update acc ⋯} is a demand on the parameter \code{acc}, so the
lambda's $\mathit{use}(2) \ni \mathsf{W}$, and its result is $\{\pi_2\}$. The lambda writes a
\emph{parameter}, not a capture, so it is not once. The edge ``the lambda writes its second parameter, so
\code{foldl} must supply it owned'' holds. The elements are \code{Int}s, which cross, so \code{update}'s
inner callback needs no exclusivity. \emph{Accepted}: the accumulator is written in place at every step,
which is the building pattern our prototype study measured at 0.14--0.47 times the persistent
representation's time.

\section{Prepend, then reverse}

\begin{Verbatim}
evens xs = List.reverse (List.foldl xs [] λx acc → if Int.mod x 2 == 0 then [ x, …acc ] else acc)
\end{Verbatim}
Elm's accumulator idiom, carried over. The callback's construction consumes its second parameter; on the
other arm it returns it unchanged, so its result is $\{\pi_2\}$ on both arms and its $\mathit{use}(2)$
contains $\mathsf{W}$. \code{foldl} supplies the accumulator owned. Each prepend writes the slot in front of
the accumulator's first element and returns a new header; when the room in front is used up, the base is
moved to a larger array with room proportional to its length. \code{List.reverse} builds a new list, or
returns its input when it is shorter than two. \emph{Accepted}, linear, in place.

\section{Grouping into a dictionary}
\label{app:groupby}

\begin{Verbatim}
groupBy xs key =
    List.foldl xs Dict.empty λx d →
        group = Maybe.withDefault (Dict.get d (key x)) []
        Dict.insert d (key x) [ …group, x ]
\end{Verbatim}
\code{Dict.get}'s inferred summary says its result aliases a value inside its dictionary, at the folded
path $\langle\mathit{Dict}\rangle.v$, so \code{group} holds a cell that \code{d} also holds. At the
construction \code{[ …group, x ]}, the holders of the cell are \code{group} (the base) and
$(d, \langle\mathit{Dict}\rangle.v)$, and \code{d} is live afterwards, because it is passed to
\code{Dict.insert}. The program is \emph{rejected as real sharing}, with a message that says \code{d} still
holds the list and is read by \code{Dict.insert} on the same line, and offers to update the group where it
is:
\begin{Verbatim}
Dict.update d (key x) (λg → Just [ …Maybe.withDefault g [], x ])
\end{Verbatim}
Here \code{Dict.update : Dict k v, k, (Maybe v → Maybe v) → Dict k v} looks the value up, calls the
callback, and inserts the result. Its callback is supplied an owned value by the one asserted row of the
dictionary module, whose argument is that the insert that follows reads neither the old value nor a key
that aliases it, provided the contents are exclusive---keys included. The rewritten program is accepted
\emph{provided \code{d}'s contents are exclusive}, and here they are, from \code{Dict.empty} on: every
value stored is either \code{[ x ]}, built by pushing onto a fresh \code{[]}, or the result of a
construction on an owned value, each a distinct cell with no other holder; the keys are of whatever type
\code{key} returns, and when that type crosses, as a string or an integer does, they hold no cell at all.
No lookup leaves a live alias. This is the program whose silently quadratic behaviour under reference
counting motivated Huisinga's analysis for Lean \citep{huisinga2023lean}; here it is a message with the fix
on it, and the fixed form is checked statically rather than counted at run time.
