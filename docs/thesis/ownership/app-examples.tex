\section{TodoMVC's toggle}
\label{app:todomvc}

The application's own code is:
\begin{Verbatim}
init : Model × Cmd Msg
init = ⋯                                   -- a top-level value
Toggle id → changed model (List.map model.todos λt → if t.id == id then { t | completed = not t.completed } else t)
changed model todos = ( { model | todos = todos }, save todos )
save todos = Cmd.do λ⊤ → saved (Storage.set Local key (encode todos))
\end{Verbatim}

\paragraph{As written, on its own platform.} \code{List.map} builds a new list and is not a demand, and
nothing else in the arm writes in place. There is nothing to check: the program is accepted, on the
template runtime it runs on, and nothing in it is written in place. The template runtime's row escapes
every list \code{view} shows, and \code{init}'s cells are escaped as a top-level value's, but neither
matters when there is no demand.

\paragraph{Rewritten with an in-place form, on the template runtime.} Replace \code{List.map} by an
in-place form (Change~1), \code{List.updateEach model.todos (λt → ⋯)}. The demand is on the cell at
$(\mathit{model}, .\mathit{todos})$. \code{view} renders \code{model.todos}, and the template runtime keeps
what it rendered, so the cell is escaped from the first render: \Unescaped\ fails, and the message says
that the page still shows the list. \emph{Rejected.}

\paragraph{Rewritten with an in-place form, on the direct platform.} Now the runtime keeps no rendered
list (\Obl{P1}--\Obl{P4}). Three further facts decide it.
\begin{itemize}
\item \code{init} must be a function (Change~12). As a value, its cells are escaped, and \Unescaped\
fails at the first toggle. As a function, its result is fresh at every call.
\item \code{save}'s thunk captures \code{todos}, the list the arm returns in the model, and the runtime
keeps the command. \code{Cmd.do}'s thunk here cannot suspend (\code{Storage.set} is synchronous), so on a
platform that drains such commands before the next message (\Obl{P7}) the capture is held only until then,
and \code{model.todos} is not escaped at the next entry. Without \Obl{P7} it is escaped, and the next
toggle is rejected as possible sharing; the fix the message offers is to encode before the command is
made, \code{text = encode todos}, so that the thunk captures a string.
\item \code{changed}'s summary is $\unused$ at $\pi_1.\mathit{todos}$, because its record update replaces
that field, and $\mathit{res}(.\mathit{todos}) = \{\pi_2\}$. Passing the old \code{model} to it after the
in-place edit is therefore not a use of the edited cell. (An earlier version's lattice had no $\unused$,
and this step failed.)
\end{itemize}
With all three, the entry protocol finds \code{model.todos} owned, unaliased and unescaped at every entry;
the operand's only holder is $(\mathit{model}, .\mathit{todos})$; the lambda captures \code{id}, a scalar
that crosses, and consumes nothing, so it is not once and may be called many times. \emph{Accepted}:
\code{a[i] = f(a[i])}.

\section{A table application's row swap}

\begin{Verbatim}
SwapRows → { model | rows = List.swap model.rows 1 998 }
\end{Verbatim}
On the direct platform, with \code{init} a function. \code{swap} is a writer. The holders of
$(\mathit{model}, .\mathit{rows})$'s cell are that path itself and the runtime's instance array, which holds
items for identity comparison only (A4); no arm captures \code{rows} in a command, and no path of the model
aliases it, so the entry protocol finds it owned. The model is dead after the arm. \emph{Accepted}: two
assignments on the plain array. The platform's edit script compares row items, never the list's identity.
In the persistent representation the same message performs two \code{set}s, each a path copy through the
trie at that size, and a spread of the model record; in place, the swap is two array writes.

\section{A histogram by fold}

\begin{Verbatim}
hist = List.foldl samples (List.repeat 0 1000) (λs acc → List.update acc (bucket s) (λn → n + 1))
\end{Verbatim}
\code{repeat}'s result is fresh. \code{foldl}'s class supplies its callback a borrowed element and an
owned accumulator (provenance $\pi_2$ and the callback's own previous result), calls it many times, and
keeps none of it. In the lambda, \code{List.update acc ⋯} is a demand on the parameter \code{acc}, so the
lambda's $\mathit{use}(2) \ni \mathsf{W}$, and its result is $\{\pi_2\}$. The lambda writes a
\emph{parameter}, not a capture, so it is not once. The edge ``the lambda writes its second parameter, so
\code{foldl} must supply it owned'' holds. The elements are \code{Int}s, which cross, so \code{update}'s
inner callback needs no exclusivity. \emph{Accepted}: the accumulator is written in place at every step,
which is the building pattern our prototype study measured at 0.14--0.47 times the persistent
representation's time.

\section{Grouping into a dictionary}
\label{app:groupby}

\begin{Verbatim}
groupBy xs key =
    List.foldl xs Dict.empty λx d →
        group = Maybe.withDefault (Dict.get d (key x)) []
        Dict.insert d (key x) (List.push group x)
\end{Verbatim}
\code{Dict.get}'s inferred summary says its result aliases a value inside its dictionary, at the folded
path $.\mathit{contents}$, so \code{group} holds a cell that \code{d} also holds. At the demand
\code{List.push group x}, the holders of the cell are \code{group} (the operand) and
$(d, .\mathit{contents})$, and \code{d} is live afterwards, because it is passed to \code{Dict.insert}. The
program is \emph{rejected as real sharing}, with a message that says \code{d} still holds the list and is
read by \code{Dict.insert} on the next line, and offers to update the group where it is:
\begin{Verbatim}
Dict.update d (key x) (λg → Just (List.push (Maybe.withDefault g []) x))
\end{Verbatim}
Here \code{Dict.update : Dict k v, k, (Maybe v → Maybe v) → Dict k v}. Its callback is supplied an owned
value by the one asserted row of the dictionary module, since its body holds the old value at a key the
path domain cannot name. The rewritten program is accepted \emph{provided \code{d}'s values are
exclusive}, and here they are, from \code{Dict.empty} on: every value stored is either \code{[ x ]} pushed
onto a fresh \code{[]} or the pushed result of a destructive read, each a distinct cell with no other
holder, and no lookup leaves a live alias. This is the program whose silently quadratic behaviour under
reference counting motivated Huisinga's analysis for Lean \citep{huisinga2023lean}; here it is a message
with the fix on it, and the fixed form is checked statically rather than counted at run time.
