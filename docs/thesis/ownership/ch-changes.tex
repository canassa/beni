\chapter{Changes to the Language and Library}
\label{sec:disc-options}

beni's specification can change where the checker needs it. This chapter gives each change's reason,
what it buys, what it costs developers, which decision already recorded in the language's specification
it touches, and how it weighs against the principle of Chapter~\ref{sec:discussion}, that a restriction
must buy a guarantee. The changes fall into three groups. Changes 1--4 are \emph{decided}: they define the
language the checker is designed for (\S\ref{sec:bg-language}). Changes 5--8 are \emph{required} by the
design as it stands: without them the soundness argument does not go through, or the idioms of
Chapter~\ref{sec:idioms} are rejected on the platform that runs them. Proposals O1--O7 are \emph{open}:
each would buy precision, speed or convenience, each has a cost, and none is assumed by the rest of the
thesis.

\section{Decided changes}

\subsection*{Change 1: list construction consumes its base}
\phantomsection\addcontentsline{toc}{subsection}{Change 1: list construction consumes its base}

In \code{[ x, …acc ]}, \code{[ …acc, x ]}, \code{[ …acc, …ys ]} and \code{acc ++ ys}, the first spread, or
the left operand of \code{++}, is the base: its array is reused in place, at either end, and the other
operands and the elements are only read. A literal with no spread allocates; a pattern only reads; a
construction whose base is used again is an error whose message offers \code{List.copy}
(\S\ref{sec:model-demands}).

\emph{Reason.} Accumulators, folds, recursive builders and \code{update} arms are written with list syntax,
and with construction consuming they run in place with no new name (Chapter~\ref{sec:idioms}).

\emph{Costs.} The checker meets a demand at every spread and every \code{++} on lists, so its precision
on idioms carries the design. The programmer learns which operand is reused. A version that is kept and
later extended needs an explicit copy.

\emph{Recorded decisions it touches.} It keeps the language's decision that no way of building a list by
prepending is quadratic for every accumulator, fold, recursive builder and TEA list, and reverses it for
a persistent stack whose old versions are read later, which now needs a copy per kept version; the test
program guarding that decision needs \code{List.copy} at the version it keeps
(\S\ref{sec:idioms-rejected}). It withdraws the identity promise that \code{[] ++ ys} is \code{ys} itself
(\S\ref{sec:model-demands}). It agrees with the decision that \code{++} on lists calls the list library's
append.

\emph{Against the principle.} It buys the cost guarantee for the idioms people write; its restriction,
that a base be dead, protects against a silent wrong answer.

\subsection*{Change 2: no silent fallback, and \code{List.copy}}
\phantomsection\addcontentsline{toc}{subsection}{Change 2: no silent fallback, and List.copy}

The compiler never copies a list, and never chooses a slower algorithm, to make an edit safe.
\code{List.copy : List a → List a}, new, shallow and fresh, is the explicit copy, and every $O(n)$ copy a
program pays for is written as one.

\emph{Reason.} A silent copy makes the cost model depend on facts the programmer cannot see; in our
prototype study one turned a fold 8.2 times slower than the persistent baseline (\S\ref{sec:bg-measure}).

\emph{Costs.} Programs that share on purpose write the copy. There is no warning mode that copies.

\emph{Against the principle.} \code{List.copy} is the escape hatch the principle asks for.

\subsection*{Change 3: \code{eq} and \code{compare} only read}
\phantomsection\addcontentsline{toc}{subsection}{Change 3: eq and compare only read}

A type's \code{eq} and \code{compare}, derived or written, must only read their arguments; one whose
inferred summary writes, keeps or returns a cell of an argument is an error at its declaration
(\S\ref{sec:inf-generic}).

\emph{Reason.} \code{==} on a list, a derived \code{eq} and every \code{where a.eq} function call the
element type's \code{eq}, often with one cell as both arguments. An \code{eq} that edited its argument
would write that cell twice, behind every caller's back.

\emph{Buys.} The guarantee that \code{==} and \code{<} never change a value, on which the summaries of list
equality, dictionaries, sets and sorting rest unconditionally.

\emph{Costs.} A text search finds over a hundred public \code{eq} and \code{compare} declarations in the
core library, the platforms, the test programs and the examples; those we read only read. An \code{eq}
that wants to sort compares sorted copies, \code{List.sort a == List.sort b}. A \code{Debug.log} inside an
\code{eq} stays legal.

\emph{Against the principle.} A restriction that buys a guarantee---no silent change to a value through a
comparison.

\subsection*{Change 4: \code{init} is a function, and top-level lists are shared}
\phantomsection\addcontentsline{toc}{subsection}{Change 4: init is a function, and top-level lists are shared}

A TEA program's \code{init} is \code{init : ⊤ → Model × Cmd Msg}, or a function of the program's flags,
called by the platform once per mounted program; a \code{Reset} arm may call it again. A top-level value
holding a list is shared and never edited in place; a program edits a list a function returns, or a
\code{List.copy} (\S\ref{sec:model-check}).

\emph{Reason.} A value \code{init} would put the same arrays in every mount and in every \code{Reset}, so
editing them in place would change what the next mount or reset starts from. Rust, Clean and Futhark treat
global values the same way.

\emph{Costs.} Every platform's program constructor changes; a text search finds 253 test programs, examples
and benchmarks that call one, nearly all with \code{init} as a value, and each adds \code{⊤} and a
lambda---or, where \code{init} is a top-level constant, \code{⊤} on its definition. The constructor
modelled on Elm's \code{Browser.sandbox}, whose \code{init} is a value, diverges from Elm's API; the rule
forces that divergence. A program that seeds its model from a top-level list is rejected at its first
in-place edit until it builds or copies the list in \code{init}.

\emph{Against the principle.} A platform API change that buys a guarantee: no mount or reset sees another's
edits.

\section{Changes the design requires}

\subsection*{Change 5: ownership words on \code{foreign} declarations and foreign types}
\phantomsection\addcontentsline{toc}{subsection}{Change 5: ownership words on foreign declarations and foreign types}

A \code{foreign} parameter may say \code{unused}, \code{borrowed}, \code{aliased}, \code{escaped} or
\code{consumed}, and a function-typed one how often it is called; a result \code{fresh}, ``is parameter
$i$'', \code{escaped} or \code{unknown}, and whether it is exclusive. A \code{foreign type} may say that it
crosses. The core library and the platforms may assert a summary that a body cannot show; every other
package may only \emph{narrow} an inferred one. A public beni declaration \emph{may} carry the same words in
its annotation, and the inferred summary must then be at most what is written: an annotation can claim
more of an argument than the body takes, never less, and freezes the interface.

\emph{Reason.} A \code{foreign} has no body, a foreign type has no definition, and the core library's
functions over \code{Js} have bodies that cannot show what they promise (A2, A6, A10). For public beni code
the optional annotation answers interface churn: annotated declarations were the ones whose interfaces did
not change in our churn measurement (\S\ref{sec:bg-modules}). At Jane Street, OxCaml interface files
carried 27\,382 locality annotations, because ``the implementations can generally infer locality, whereas
interfaces must write it down explicitly'' \citep[\S7]{lorenzen2024oxidizing}.

\emph{Costs.} A trusted vocabulary on every sibling, and the test program that pins each row. Inference is
complete without the optional annotation, so application code carries none.

\emph{Against the principle.} Required for \code{foreign}; an opt-in for public declarations.

\subsection*{Change 6: an edit is a barrier to the optimiser}
\phantomsection\addcontentsline{toc}{subsection}{Change 6: an edit is a barrier to the optimiser}

The language definition says that a demand---a writer's call or a construction---is a write for the
purpose of ordering, and narrows both its statement that call-free evaluations may be ordered freely and
the optimiser's licence to fold a read of a beni value past calls, so that neither moves a read of a list
across a demand that may write it (A5).

\emph{Costs.} The single-use fold may no longer place \code{xs.length} past a construction on \code{xs}; a
small size cost, unmeasured. It is a change to the language's evaluation-order licence.

\emph{Against the principle.} No restriction on programs; a constraint on the optimiser.

\subsection*{Change 7: \code{send} writes what \code{update} writes}
\phantomsection\addcontentsline{toc}{subsection}{Change 7: send writes what update writes}

A program's \code{send} consumes a payload path only when some arm of \code{update} edits that path in
place, and otherwise only aliases it (\Obl{P6}).

\emph{Reason.} Payloads that \code{update} edits must be unique at the arm; payloads it only reads need
nothing. Consuming every payload would reject programs with no in-place edit at all, which buys no
guarantee; sharing every payload would make a list decoded in a fiber, sent and stored in the model
uneditable forever.

\emph{Costs.} A send's verdict depends on \code{update}'s summary, so it is checked at the entry fixpoint
rather than where the send is written; the message must point from the send to the arm that edits the
payload.

\emph{Against the principle.} It rejects exactly the sends whose payload an arm edits in place.

\subsection*{Change 8: a renderer skips a list by identity only if no arm edits it}
\phantomsection\addcontentsline{toc}{subsection}{Change 8: a renderer skips a list by identity only if no arm edits it}

A renderer compiles every markup site that may show a list the program edits in place---learnt from
\code{update}'s summary at the program constructor---without the skip that compares that list, or a row
item holding one, with the last by identity; such a site walks its rows (\Obl{P7}).

\emph{Reason.} An in-place edit keeps a list's identity, so a skip on identity would leave the page showing
the old list. Without the change, every in-place edit of a rendered list is an error on beni's template
runtime, which under Change~1 is the idiom I5 on every rendered list.

\emph{Costs.} Such a site compares each row's item on every render where it compared one pointer. That
cost falls on exactly the lists the program edits, and whether it is acceptable against the reference
renderer is to be measured with the existing benchmark harness before the change is adopted
(\S\ref{sec:eval-perf}). The direct platform already satisfies the obligation by design.

\emph{Recorded decisions it touches.} None of the identity promises: the renderer still relies on them for
every list the program does not edit.

\emph{Against the principle.} A runtime contract, not a restriction on programs.

\section{Open proposals}

\subsection*{O1: in-place forms of the same-shape rebuilds}
\phantomsection\addcontentsline{toc}{subsection}{O1: in-place forms of the same-shape rebuilds}

Named writers that do in place what \code{map}, \code{filter}, \code{reverse}, \code{sort} and \code{take} do
by building: \code{List.updateEach xs f} (\code{a[i] = f(a[i])}), \code{List.retain xs p} (compacts in
place), \code{List.reverseInPlace}, \code{List.sortInPlace} and \code{List.truncate xs n}. The names are
illustrative; the point is that they are distinct, and \code{map} and \code{filter} keep building. They
would let TodoMVC's toggles and deletions run in place. A spelling that made \code{map} itself a writer in
some positions does not survive helpers, which have one summary however they are called. Cost: a second
function per rebuild in the library---the duplication FP\textsuperscript{2} identifies as the cost of
static uniqueness typing, ``where a single function can have multiple different implementations''
\citep[\S1.4.1]{lorenzen2023fp2}---and a choice the programmer must learn. To be decided on how often the
external corpus applies these functions to a list that is unique and dead at the call.

\subsection*{O2: drop the identity promises}
\phantomsection\addcontentsline{toc}{subsection}{O2: drop the identity promises}

Functions that build would return a fresh array always, instead of their input when the result would
equal it. \emph{Buys:} $\mathit{res} = \{\fresh\}$ for \code{filter}, \code{map} and their kin, so an edit of
the result never demands the source (\S\ref{sec:hard-pipelines}). \emph{Costs:} the renderer skips a
\code{<For>} when its list is the same object as last time, and these promises are what make an unchanged
filtered or mapped list the same object; without them, a \code{view} that renders
\code{List.filter model.todos visible} hands the renderer a new array on every render, and every unrelated
message walks every row, keyed matching included. \emph{Conflicts with} the language's recorded decision that
these operations return their input itself, on which its rendering strategy rests. We recommend keeping
the promises: their cost to the checker is precision only where the source is used again, which the
idioms do not do.

\subsection*{O3: the policy for room in front of a list}
\phantomsection\addcontentsline{toc}{subsection}{O3: the policy for room in front of a list}

How much free space a prepend leaves before a list's first element, whether plain arrays carry some from
birth, and when a view is flattened (\S\ref{sec:compiler-backend}). Any policy that grows the space in
proportion to the length keeps prepending amortised $O(1)$; the choices trade memory and the frequency of
views against the cost of the first prepend onto a plain array. To be measured.

\subsection*{O4: interfaces publish whether a type can hold a list}
\phantomsection\addcontentsline{toc}{subsection}{O4: interfaces publish whether a type can hold a list}

The declaring module of an opaque type computes whether it crosses and publishes the bit, so importers can
drop its paths. Without it, an opaque type is tracked under its opaque step, which is sound and costs
width rather than precision (\S\ref{sec:model-cells}). Cost: interface content, and churn when a type's
definition gains or loses a list.

\subsection*{O5: a persistent vector as a library}
\phantomsection\addcontentsline{toc}{subsection}{O5: a persistent vector as a library}

A core module holding the current trie, written in beni with no in-place writes, for programs that keep
many versions. Cost: a second sequence type in the library, where the language deliberately has one; as a
library module it has the status of a dictionary, not of \code{List}.

\subsection*{O6: command constructors that take values}
\phantomsection\addcontentsline{toc}{subsection}{O6: command constructors that take values}

Platform commands that persist or send data---storage, HTTP bodies, logging---take the value to send
(\code{Storage.save key text}) rather than a closure that computes it later, as Elm's HTTP library takes an
encoded body. \emph{Buys:} the commonest escape in TEA programs disappears from idiomatic code
(\S\ref{sec:hard-fibers}). \emph{Costs:} a body that genuinely needs the list later must say so with
\code{List.copy}; more command constructors in each platform.

\subsection*{O7: summaries split by the message's constructor}
\phantomsection\addcontentsline{toc}{subsection}{O7: summaries split by the message's constructor}

\code{update}'s summary published per constructor of its message, so the entry check can tell which arm a
view-event payload reaches (\Obl{P6}). \emph{Buys:} one \code{onClick=\{Keep model.rows\}} no longer
blocks in-place edits of \code{model.rows} in other arms. \emph{Costs:} a summary per constructor of the
message type, in the interface. To be decided on how often the view-event tag fires.
