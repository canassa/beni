## 1. How the work is run

The owner directs; a manager session plans, briefs Opus agents in git worktrees, reviews their
reports, rebases, runs the gates, merges and pushes to `master` (standing permission), and writes the
diary. Standing rules worth re-reading before any brief: CLAUDE.md rules 1–10 (spec first; never
renumber `docs/design/`; black-box tests, red first; gates green; determinism — including **no
dependence on where the project lives or on module order**; `foreign` privileged; guarantees not
restrictions; Solid-speed UI; rule 9 precise errors, no broad catch; rule 10 never bend the design to
pass a check — stop and report). Owner preferences in the auto-memory index: benchmarks under five
minutes and all candidates in one table; minification never slows anything ("real performance, not
noise"); Effect v4 parity for the fiber runtime; the task runtime as small and tree-shakeable as
possible (every real app ships it); Elm's API design for new libraries; agents' "confirm first"
choices go to the owner **before** a mechanical commit. **The owner asked for no new agents until
told otherwise** (still in force at this handover).

Merging habits that bit this session: check the merge itself succeeded before gating and pushing;
rebase onto master first and re-record run hashes (`zig build test-run-hashes`) — conflicts are almost
always `.run-hash` files, resolved by taking either side and re-recording; `/tmp` is an 8 GB tmpfs —
clean the session scratchpad when it fills (the page driver's cache now lives in `zig-out/`).

- `Debug.toString` inside a polymorphic function still prints by runtime representation (a tuple as a
  record) — documented in `language.md` Appendix B, pinned by `run/DebugLogShapes`.
- The specialiser's round caps can in principle still make a result order-dependent beyond the cap;
  the solver removes the caps.
- CLAUDE.md's gate timings ("about 6 s / 10 s after an edit") predate the embedded checked core and
  platform pack, which adds a maker compile and run after an edit under `src/`; re-measure on a quiet
  machine and update.
- The 27-program development-output difference after the `⊤` migration is markup names carrying BIR
  instruction numbers (`X$t142`); release output is byte-identical. Names derived from instruction
  numbers move whenever unrelated code before them changes.
- `type_identity_unknown` refuses a key type mentioning a phantom variable with no requirement — by
  design; the core intrinsic `Js.fingerprint` takes an `EQ` witness (a documented wart).
- `Rt.trimmed` (keyed `For`'s prefix/suffix/swap pass) is kept deliberately — the owner declined its
  removal for speed.
