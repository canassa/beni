# Typed Inline performance validation

The typed Inline queue remains unlanded until its applicable performance gates
pass. Byte compliance and browser behavior alone do not establish UI or VM
allocation parity. No guarantee or budget is waived.

## Evidence already obtained

The frozen numeric-marker/count candidate passes all 55 affected individual
release byte limits and all 161 release fixtures have no growth. Inline behavior
passes HappyDOM and Chromium. Direct dispatch has a narrow original-compiler
microprobe; it is not the full UI comparison or an allocation measurement.
Manager scratch retains raw receipts and exact source/compiler provenance.

## Measurement prerequisites

The official report 29 driver remains unchanged. Its table app and static-heavy
app both use String class attributes, which the actual original compiler rejects.
Issue #1378 fills this existing compiler limit under the decided Html semantics.
The class fix must preserve attribute escaping, value comparisons, evaluation
order, HTML/SVG behavior and prerendering. The generated static driver records
mount throttling separately and checks every counter in the same evaluation.

The table also needs the keyed renderer specified in browser-inline.md §9. It
cannot be made compilable merely by changing its List model to Dict. The current
Inline emitter rejects every For; Dict is still tree-backed and the checker
requires List collections. The four S2 decisions were already made on
2026-10-25; implementation size is not a reason to request another decision.

S2a's Dict write-set tags and §8.4's root factories already exist. Revalidate
those foundations rather than rebuilding them. Remaining prerequisites include
ordinary ownership enforcement (#320/#681), the decided plain List (#321),
ordered pair-index Dict and keyAt (#961), Dict For checking/browser-tea rendering,
Inline row units/reconciliation and write-directed edits, and the explicit
schema-freshness dependency #879. Follow their normative designs, keep v1 frozen,
and establish v2 proofs without flags, copying fallbacks or runtime exemptions.

## Comparison provenance

Retain the actual original Debug compiler unchanged for baseline fixtures and
microprobes. If both UI subjects need the same scalar-class compatibility fix,
build a separate baseline from the original source plus only that fix and label
it explicitly. It is not the original compiler. Both table subjects must compile
the same Beni source following the decided Dict contract, preserve the official
nine operations and DOM, and run through the unchanged report 29 harness.

Measure old-compatible runtime, final candidate, pinned Solid 2 and vanilla with
raw samples, all postconditions, per-operation medians and IQR, both prescribed
throttling and unthrottled runs. Run static-heavy separately against Solid 2.
Preserve exact source, compiler, entry, dependency and browser hashes. A quiet
Dagon window is required. Do not omit failed samples, aggregate ratios into a
parity claim, introduce a fake Inline flush hook or edit application JavaScript.

Public worker launching and complete typed-runtime claims remain gated by their
own realm, Wire, callback and ownership proofs. Independent compiler correctness
and planning checkpoints may proceed while this queue remains pending.
