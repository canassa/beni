## 2026-11-07 13:51 CET — Worker realm allow-list and release probes (#2206, #2207)

**What I did**

- Replaced `RealmCheck`'s 13-name deny-list with an allow-list per worker
  realm: `src/js/WorkerGlobals.zig`, one table generated by
  `scripts/worker-globals.mjs` from the pinned Webref IDL 3.86.0 and the
  ECMA-262/402 global object (dedicated 447 names, shared 399, service 438).

  native pass.

  probes `setImmediate` that way and every worker build needed it.
- `Print.bareName` keeps `globalThis.` for names off the realm's list in a
  worker, so `document===undefined` became `globalThis.document===undefined`.
- 24 refusal fixtures (`build/bad/dedicated/RealmJ*`), two Chrome pages
  (`browser/dedicated/RealmProbeSafe`, `RealmAvailableSafe`), one emit golden.

- Spec: `workers.md` §4 *The worker global allow-list*; `backend.md` §9 item 8

  the owner's choice of per-export realm declarations).

**What I learned**

- An allow-list surfaces trusted feature probes the deny-list never saw:
  `setImmediate` in core. Refusing it would refuse every worker; the narrow
  def-use probe rule keeps the check sound without touching core's bytes.
- `fixedName`-style "host names are always free" over-refuses siblings that
  name parameters `document` or `event`; without scopes, check 3's bindings are
  the only consistent choice, and the gap is recorded, not hidden.
- Pages, fibers and apps are byte-identical (`bench/size.mjs --pages-only`
  trees diffed); worker downloads unchanged except a probe's +11 raw bytes.
