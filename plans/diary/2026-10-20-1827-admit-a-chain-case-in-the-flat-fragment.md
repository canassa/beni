**What I learned.** The checker infers the link arm of a chain case even when the chain is statically empty: `endChain` builds `.list [fresh] .bottom true` and the head is bound to the element abstract, so the arm is dead code with a bottom integer in scope, which flows into records (`record [h]`), result slots (`ok h`, both slots bottom) and, through a result case that skips both arms, into a bottom at any type. A static relation of "flat or bottom at the top" is not closed under records, and the join of a live arm with a dead one puts a weak abstract into a result's dead slot; so bottom must be admitted everywhere statically, and the runtime side excludes it through the tags, which already pair the checker's view with the runtime value. The static theorem then cannot derive an operand's run from its shape (a field of a bottom record throws "abstract projection"); it must extract the run from the accepted inference and derive the shape from the run. A `cases h : e` on the checker's run also rewrites `e` in the goal, so a component the goal mentions is `rfl` afterwards, not `h`. `namesAt` and `obsTyped` are not `rfl`-reducible on a bottom or an integer; `simp` with their definitions is. An anonymous-constructor component `fun h => by cases h, …` parses the comma into the `cases` targets; wrap the lambda in parentheses or use `nomatch`.
