## 2026-11-06 01:10 CET — An inline program constructor's body throws a named defect (#1232)

**What I did.** `browser-inline`'s `Tea.sandbox`, `element`, `document` and `application` had the body `unreachable app`, and `unreachable _ = Js.to Js.undefined`. Now each body is `unreachable "Tea.<name>"`, and `unreachable` throws `new Error(...)` with `Js.throw` and `Js.construct`. The message names the constructor and says that the `inline` lowering did not compile the call. I wrote the rule first as dated amendments in `browser-inline.md` §10.5 and `boundary.md` §9.4.6 (`Lowering.constructs`), and re-justified the `entry` words in `ownership-checker.md` §24.8. I set the four new hashes in `word-bodies.txt`. I added `build/bad/inline/ConstructorsAsValues`, which refuses all four constructors as values. I tried more shapes than the #1228 review, and none reaches a body, so no fixture shows the throw. I built all 222 inline fixtures with a base and a head compiler, in development and release. The release trees are the same byte for byte. In the development trees only `_platform/Tea.mjs`, its map and the manifest change. Opened #2106.

**What I learned.** Every development build of an inline page writes `_platform/Tea.mjs` with the body of the called constructor, on `master` too, and no module imports that file. Reachability follows the callee edge of the BIR `call`, but with `Lowering.constructs` the lowering never writes the callee. So "reachability keeps the bodies out of every page" is true of what a page loads and of release trees, not of development trees. `bench/size.mjs --pages-only` has no `browser-inline` line, so it cannot measure an inline change: build the corpus fixtures with both compilers and compare the trees. A change to a platform module's `--!` comment changes its generated `skills/beni/references/api-*.md`, and so does a change of a value's inferred effect: run `zig build skill-api` before the gates. A base compiler for a change that touches only an embedded `.beni` file is cheap: put the base file in place, run `zig build --prefix <scratch>` with the same cache, and put the head file back.
